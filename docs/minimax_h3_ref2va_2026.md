# MiniMax-H3: референсы (Ref2VA) и ключевые кадры — 2026-09

MiniMax-H3 выпущена двумя чекпойнтами с **одинаковой архитектурой** DiT и
разными весами:

| Чекпойнт | Задачи | Вход |
|---|---|---|
| `FL2VA` | text→video, первый/последний кадр | текст, 0–2 картинки |
| `Ref2VA` | reference→video | текст + до 9 картинок, 3 видео, 3 аудио (≤ 12) |

VAE, audio-VAE, энкодер Qwen3-VL, токенайзер и процессор у них совпадают байт в
байт — отличается только `transformer` (66,3 ГБ). Бандл энкодера общий.

## Как референсы попадают в модель

Отдельной ref-ветки в DiT нет — референсность складывается из трёх вещей
(эталон — `diffusers/modular_pipelines/minimax_h3`):

1. **Презентация для Qwen3-VL.** Перед промптом идут метки по порядку
   референсов, со своей нумерацией у каждого типа: `<Picture i>: ` + vision-блок,
   `<Audio j>: ` (звук в энкодер не идёт), `<Video k>: ` + по блоку
   `<0.2 seconds>` + vision на каждую пару кадров (видео читается на 2 fps).
   У видео со звуком метка `<Audio j>: ` стоит **перед** `<Video k>: `.
2. **Латенты.** Картинки и видео кодирует видео-VAE, звук — audio-VAE (среднее,
   без сэмплинга). Визуальные строки зашумляются до `t = 0,999` и держатся весь
   денойз, звук идёт чистым (`t = 1`); шаг планировщика пишет только целевые
   строки.
3. **Раскладка** `[текст | блоки референсов | целевое аудио | целевое видео]` с
   общими RoPE-часами: картинка двигает их на 1, аудио — на число своих
   латентов, видео — на `max(аудио, 5/3·(1, 4, 4, 4, 4, …))`.

Порядок референсов поэтому **семантический**: тот же набор в другом порядке —
другой запрос.

Нормализация: картинка — короткая сторона 2048, кратно 32 (`max`, как у
выпущенной модели) либо вниз до площади кадра (`match`, по умолчанию: строки
референса едут через каждый шаг, `max` в разы медленнее); видео — 24 fps, холст
своего аспекта по правилу 768p, обрезка по длине генерации и вниз до `17n + 5`
кадров для VAE; звук — 32 кГц стерео по длине генерации. Декодирует и
масштабирует ffmpeg (LANCZOS), поворот из display matrix учтён.

## Движок (synaptix)

- `synaptix-video-minimax-h3::refs` — `RefSource`, `validate` (лимиты),
  `decode` (ffmpeg → `RefMedia` на хосте), `encoder_inputs` (пункты презентации
  + vision-блоки), `encode_latents` (`RefBlock` + cond-строки в порядке
  раскладки), `labels` (метки для промпта), `has_audio_stream`.
- `VaeEncoder::encode_clips` — видео клип за клипом с хоста: 15 секунд 768p —
  это гигабайты пикселей.
- `denoise_av` сверяет число cond-строк с раскладкой.
- CLI: `synaptix h3 <dir> --ref a.mp4 --ref b.png --ref c.wav
  [--ref-mute-video] [--ref-image-size match|max]` — порядок флагов значим,
  вариант `ref2va` выбирается сам.

## Ноды

**H3 References** — один упорядоченный список вместо трёх разнотипных нод: вход
`av_latent` (по нему обрезаются видео и звук), выход `refs` → в `H3 Text
Encoder.refs` и `H3 Sampler.refs`. У каждой строки нода показывает метку, под
которой референс увидит модель (`<Video 1> + <Audio 1>`), — на неё и ссылается
промпт. У видео со звуком есть переключатель дорожки; стрелки меняют порядок.
Нумерация `<Audio j>` зависит от того, есть ли в файле аудиопоток, поэтому файл
пробуется (ffprobe) при добавлении, а не при прогоне.

Сэмплер кодирует референсы **до** загрузки DiT (VAE нужна свободная карта),
проверяет, что чекпойнт — Ref2VA, и что референсы декодированы под ту же длину,
что и латент. Референсы и ключевые кадры вместе не подключаются — это разные
чекпойнты.

**H3 Keyframe** теперь сериализуется (`image_path`, `frame_slot_idx`,
`resize_idx`): раньше шаблон терял слот «последний кадр», а агент не мог
подставить картинку через `attachment:`. Заодно заработал `resize_idx`: кадр
кладётся на холст генерации (stretch / center_crop) — прежде VAE кодировал его в
родном размере, и число cond-строк расходилось с раскладкой.

Шаблон: `builtin-h3-ref2va`.

## Агент чата

Закрытый H3-Context-IR у MiniMax переписывает запрос пользователя в структуру из
шести секций (`subject_definitions`, `summary`, `retention_analysis`,
`detailed_description`, `overall_soundscape`, `non_diegetic_music`). Локально эту
роль играет агент:

- `pipelines open` шаблона с H3 отдаёт формат промпта: `h3_prompt_ref.md` для
  графа с H3 References, `h3_prompt_base.md` для text→video и ключевых кадров
  (сжатые версии официального `skills/h3-prompt-writing`);
- `open` / `apply` / `graph` отдают метки референсов:
  `H3 References (node 10) — refer to them in the prompt by these tags:
  <Video 1> + <Audio 1> = dance.mp4 …`;
- `set_state` ноды: `{"items": [{"path": "attachment:dance.mp4", "use_audio":
  true}, …], "image_size_idx": 0}`. Внутри `items` ссылка `attachment:` даёт
  **исходный** файл, а не derived-копию: для аудио derived — это WAV 16 кГц
  моно под ASR, а референс голоса кодируется в 32 кГц стерео.

Сценарий «загрузил три видео и описал»: агент смотрит вложения своим зрением
(`view_media`), открывает `builtin-h3-ref2va`, одним `apply` ставит пути
чекпойнта, `items` и длительность, по меткам из ответа пишет шестисекционный
промпт, вторым `apply` кладёт его в TextView и запускает `run` с
`free_vram=true`.

## Проверка

- `cargo test -p synaptix-video-minimax-h3 --test refs` — правила холста, кадров,
  меток, презентация, живое декодирование через ffmpeg (без GPU).
- `cargo test -p synthos --features testing --lib -- minimax_h3 templates::` —
  метки, круговая сериализация, шаблон.
- E2E без GUI: `H3_REFS=a.mp4:b.png:c.wav H3_ENCODER=<encoder.syn>
  h3_smoke <ref2va.syn> out.mp4 640 384 3 8`. `H3_FORCE_REFS=1` пускает путь
  референсов на весах FL2VA — картинка бессмысленная, но раскладка, VAE и денойз
  проверяются без Ref2VA.

## Упаковка Ref2VA

```sh
SRC=/path/to/MiniMax-H3/Ref2VA
syn-pack -o $OUT/minimax-h3-ref2va.syn \
  --id minimax-h3-ref2va --version 1.0.0 --arch minimax-h3 --purpose video \
  --component transformer:$SRC/transformer \
  --component video_vae:$SRC/video_vae/source \
  --component audio_vae:$SRC/audio_vae \
  --files $SRC
```

Энкодер — прежний `minimax-h3-qwen3vl-encoder.syn`.

## Чего нет

- H3-Regenerate-2K не открыт — локально только 768p.
- Разреженное внимание не выпущено: три видео-референса по 5 с плюс цель — это
  порядка 125 тыс. токенов при полном внимании.
- Ресайз ключевого кадра — билинейный (эталон — LANCZOS); презентация энкодеру
  получает кадр в родном размере.
