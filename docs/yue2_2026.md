# YuE2 — песня из стиля и лирики через редактируемую партитуру (2026-09)

## Что это

YuE2 (`m-a-p/YuE2-3B`, HKUST / M·A·P и соавторы) делает полную песню с вокалом и
аккомпанементом из тегов стиля и текста. Отличие от ACE-Step и прочих: между
запросом и звуком стоит **партитура в ABC** — её видно, можно править и рендерить
заново. Один костяк **AR–NAR Mixture-of-Transformers** выполняет две разные
работы:

- **AR-путь** авторегрессивно пишет партитуру (обычный текстовый словарь), затем
  семантические токены музыки (свой диапазон словаря, 25 токенов на секунду);
- **NAR-путь** — тот же костяк, но второй, независимый комплект весов в каждом
  слое — строит акустические латенты методом flow matching (midpoint, 32 шага);
- **Oobleck-VAE** превращает латенты в 48 кГц стерео (1920 сэмплов на кадр).

Лицензия весов — CC BY-NC 4.0 с дополнительным разрешением автора: личное
использование и монетизация результатов свободны, коммерческое использование
компаниями — по отдельной лицензии.

## Устройство в движке (`synaptix-music-yue2`)

| модуль | что делает |
|---|---|
| `protocol` | спец-токены, грамматика промпта, дефолты сэмплинга |
| `tokenizer` | текстовый BPE — `qwen.tiktoken` (151 643 обычных токена) |
| `ar` | фазы партитуры и музыки поверх общего `DecoderModel` движка |
| `nar` | flow matching: AR-контекст в KV-кэше, midpoint-решатель |
| `vae` | Oobleck-декодер с тайлингом (и энкодер — для каверов) |
| `pipeline` | стадии: план → музыка → латенты → звук |

**AR-путь ведёт общий `DecoderModel`.** Слои AR лежат в бандле в обычной
HF-раскладке Llama (`model.layers.N.self_attn.q_proj.weight`), у модели есть
`q_norm`/`k_norm`, GQA 16/8, голова 128 и rope θ=10⁶ — то есть это ровно
`DecoderConfig`, и ветка получает даром префилл, flash-внимание, квант весов,
оффлоад блоков и CUDA-граф декода. NAR-двойники (`nar_*`) ему не нужны и не
запрашиваются.

**Обе AR-фазы идут по одной сессии.** После партитуры в тот же KV дописываются
`</abc>` и `<music>` — текст и партитура (тысячи токенов) не префиллятся второй
раз.

**NAR не пересчитывает контекст 64 раза.** На чанк делается один AR-проход
префикса, и его K/V остаются в кэше; NAR пишет свои K/V **в хвост того же
буфера**, поэтому у каждого шага решателя нет ни склейки, ни второй копии
контекста. Кэш под чанк выделяется сразу на `ar_len + nar_len`, внимание
NAR-позиций — плотное по «AR + NAR» без маски (причинность там не нужна),
`flash_attention(..., causal = false)`.

**Токенизатор — свой, не через `tokenizers`.** Ранги пришлось бы превращать в
список слияний, а предразбиение — в ByteLevel-регэксп GPT-2, где цифры
склеиваются; у Qwen каждая цифра отдельный кусок (`\p{N}`), и партитура вида
`Q:1/4=120` токенизировалась бы иначе, чем при обучении. Поэтому в крейте
дословный tiktoken: паттерн Qwen (fancy-regex, нужен lookahead `\s+(?!\S)`) плюс
слияние байтовых пар по рангам.

## Сверка с эталоном

Эталон снят питоновским релизом (`pip install .` из репозитория YuE2) на CPU в
FP32; входы фиксированы формулами, без RNG, и повторены в тестах.

| что сверено | результат |
|---|---|
| токенизация (7 строк, партитура, префиксы всех режимов) | совпадает ID-в-ID |
| AR-логиты последней позиции префикса | argmax тот же (163 899), топ-3 в пределах 0,05 |
| **argmax-генерация 100 семантических токенов** | **все 100 токенов совпали** |
| NAR-скорость при трёх значениях времени | mean/std в пределах 5e-3, значения — 1e-2 |
| VAE: длина, rms/min/max, первые 8 сэмплов каналов | в пределах 2e-3 |
| VAE: тайлами против полного декода | бит в бит (`max|Δ| = 0`) |

Попутно эталонный прогон показал, что оптимизированный путь релиза (`CachedNAR`
— его и повторяет наш `nar`) сходится с каноническим `nar_velocity` до 2,4e-6,
то есть сверять чанкованный путь корректно.

```sh
# быстрые (нужны бандлы)
cargo test --release -p synaptix-music-yue2
# сверка весов с эталоном: 3,6B в FP32 на CPU
cargo test --release -p synaptix-music-yue2 --test model_ref -- --ignored --test-threads=1
# сквозной прогон на GPU
cargo test --release -p synaptix-music-yue2 --test song_e2e -- --ignored --nocapture
# ноды приложения
cargo test --release --features testing --test yue2_nodes
```

## CLI

```sh
synaptix song "english, dream pop, female vocal, warm synths" \
  --lyrics-file lyrics.txt --models ~/Storage/syn_models \
  --cot full --steps 32 --seed 42 --save-abc score.abc -o song.wav
```

`--cot full` (мелодия с аккордами) | `melody` (без аккордов, для каверов) |
`off` (сразу музыка). `--abc-file` подставляет готовую партитуру вместо
сгенерированной — так работает правка: сохранить `score.abc`, поправить
гармонию и отрендерить заново. `--max-tokens` задаёт длину музыки (25 токенов
на секунду), `--quant nvfp4|mxfp8` квантует костяк, `--vae-dtype bf16` ускоряет
декод ценой отхода от эталонного тракта.

## Ноды (Нейро → YuE2)

- **YuE2 Checkpoint** — каталог моделей, опциональные override'ы костяка и
  декодера, device/quant/compute, точность декодера, «держать в памяти» →
  `model`.
- **YuE2 Generate** — `(model, style, lyrics, опц. abc)` →
  `(audio, score, latent)`. `score` — партитура в ABC: её можно смотреть
  Markdown/Text-нодой, править и подавать назад во вход `abc`. `latent` —
  акустические латенты.
- **YuE2 VAE Decode** — `(model, latent) → audio`: передекодировать латенты
  другим декодером (например `legacy`), не повторяя генерацию.

Костяк и декодер живут в общем кэше по ключу «путь + устройство + квант +
compute», в панели «Модели в памяти» видны отдельными компонентами (AR и NAR —
две записи, потому что NAR нужен только на стадии акустики). Кэш держит их через
`Weak`, поэтому «держать в памяти» — это отдельный резидентный слот с сильными
ссылками (`shared::keep_resident`); он же регистрируется в панели, откуда его
можно выгрузить. Без чекбокса после прогона делается `trim_all`, иначе пул CUDA
продолжает держать блоки.

Прогон прерывается кнопкой на карточке (и глобальным Stop): и AR-фазы, и шаги
решателя, и тайлы декодера опрашивают кооперативный флаг — генерация песни идёт
десятки секунд, дожидаться конца не нужно.

Встроенных шаблона три: «YuE2: песня», «YuE2: рендер по партитуре» (партитура
приходит из текстовой ноды — так и правят гармонию) и «YuE2: кавер по мелодии»
(`cot = melody`).

## Замеры (RTX 5090 Laptop, 24 ГБ, BF16, плотно)

| стадия | скорость |
|---|---|
| партитура (AR) | ~122 ток/с |
| музыка (AR, CUDA-граф) | ~126–130 ток/с (5 с музыки в секунду) |
| flow matching, 32 шага | 3,9 с на 30 с музыки |
| декод VAE (F32, тайл 1024) | 0,6 с на 30 с музыки |
| **итого** | **30 с песни за 13,6 с** |

Память: костяк BF16 ~7,3 ГБ (AR 4,5 + NAR 2,8), KV чанка ~1,1 ГБ на 30 с,
декодер 0,5 ГБ. Декодер грузится последним — во время генерации его вес в
памяти не нужен.

## Грабли

**Семантические токены живут в двух системах координат.** Фаза музыки выдаёт
адреса словаря (`151853 + c`), а NAR-ветка и артефакты ждут номера `0..32768`.
Перевод делает `pipeline::to_codec`; без него первый же чанк падал с
«семантический токен вне словаря».

**`narrow` + `to_dtype` на F32 не даёт раскладанный тензор.** В `phase_logits`
логиты режутся по диапазону фазы; при BF16 `to_dtype(F32)` создаёт новый
contiguous-тензор и всё работает, а при `compute = f32` возвращается тот же вид
— и `to_vec1` отвечает `NonContiguous`. Нужен явный `contiguous()`.

**SnakeBeta на CPU.** Слитого ядра там нет, а в разложении `alpha`/`beta` формы
`[C]` не транслируются на сигнал `[B, C, T]`: broadcast выравнивает формы по
последней оси. В фолбэке параметры разворачиваются в `[1, C, 1]`.

**`hf download` и `--include`.** Позиционные имена файлов отключают `--include` с
предупреждением, и `config.json` молча не скачивается — бандл тогда собирается
без архитектуры (`arch=—`), а загрузчик не знает геометрию модели.

## Что не проверено

- Ноды живьём в приложении не прогонялись: проверен тот же путь, которым идёт
  воркер (`from_parts` → `generate` → `synthesize` → `decode_with`) тестом
  `song_e2e` на GPU, но не через окно и полотно.
- Квант костяка (`nvfp4`/`mxfp8`) и `--vae-dtype bf16` собираются, но качество
  после кванта не мерилось.
- Энкодер VAE реализован (`encode_mean`), однако каверы (транскрипция
  SheetSage2 → `cot=melody`) не собраны в пайплайн.
- Малая карта (7 ГБ): костяк умеет оффлоад блоков через `DecoderModel`, у NAR
  такого пути нет — на 7 ГБ стадия акустики не проверялась.
