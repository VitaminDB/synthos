# План: низкобитные кванты, GGUF и ядра для карт ниже Blackwell (22.09.2026)

Статус: **план v2 утверждён 22.09.2026. Этапы 0 и 1 — сделаны (`prearch_stage0_device_caps_2026.md`, `prearch_stage1_block_formats_2026.md`).**

## 0. Что есть сейчас (по обходу кода)

- **Два живых формата** — NVFP4 (E2M1, блок 16, шкала E4M3, свизл под cuBLASLt) и MXFP8
  (E4M3, блок 32, шкала E8M0). Оба зашиты в `DType`, `QuantWeight`, ~22 метода `Backend`
  с именами `*_nvfp4/*_mxfp8`, `QuantKind`, `DecOutFmt`, `QuantChoice` в мастере упаковки.
- **Все GEMM/GEMV на них — только sm_120a**: `mma.sync.kind::mxf4nvf4.block_scale` и
  `kind::mxf8f6f4`. Fused NVFP4-ядра (`nvfp4_qkv_proj_shuf`, `nvfp4_swiglu_shuf`,
  `nvfp4_geglu_shuf`) — тоже FP4-MMA, альтернатив нет.
- **Дежурные обходы** частичные: MXFP8 prefill — `mxfp8_linear_dequant_fallback`
  (dequant → f16 GEMM чанками); NVFP4 — только через env `SYNAPTIX_NVFP4_WO=1`, полная
  материализация `N*K*2`. Квантующие, деквантующие и repack-ядра — sm_80-чистые.
- **Определения архитектуры нет**: NVRTC получает строковую константу (`sm_120a` в 16
  местах, часть без причины — `gemm_f16`, `gemm_f32`, `gemv_mxfp8`, `implicit_conv`, `topk`,
  `flash_*mxfp8*`). Модуль, не собравшийся под карту, роняет загрузку, кроме трёх мест с
  `Option`. Кэш PTX ключуется архитектурой — готово.
- **GGUF**: читатель v2/v3 полный, 21 из 31 ggml-типов деквантуется на CPU (нет IQ1/IQ2/IQ3,
  TQ, Q8_1/Q8_K — нет решёток), **квант при конвертации всегда теряется** (→ F16, ×4 по
  размеру), маппер только `qwen35`, токенизатор только byte-BPE, 2 регэкспа `pre` из ~30,
  прямой загрузки `.gguf` нет.
- **Перекодирования при загрузке нет**: `WeightSource::quant` не принимает dtype, политика
  `weights_storage` для пред-квантованных бандлов молча игнорируется.
- **Zero-copy стриминг ключуется адресом mmap** (`offload_pin_resolve`, зеркало экспертов,
  оффлоад блоков). Диапазоны зеркала принимают любой `&[u8]`, живущий дольше guard'а —
  это и есть крючок для перекодированных весов в RAM.
- **Железо**: только RTX 5090 (sm_120). Есть `ggml-model-Q4_0/Q8_0.gguf` + `mmproj` в
  Downloads. llama.cpp не установлен (есть в yay).

## 2. Формат SQ (synaptix quant) — предложение

Цель: любое число бит `b ∈ 1..8`, дружелюбно к GPU (деквант и dp4a без ветвлений по
формату), накладные расходы на шкалы как у K-квантов, без экзотики вроде решёток.

- **Раскладка** — вдоль K, супер-блок 256 = 8 под-блоков по 32.
  - На супер-блок: `d: f16` (шкала шкал), `dmin: f16` (шкала минимумов),
    `sub_scale[8]: u8`, `sub_min[8]: u8` — 20 байт.
  - На под-блок: 32 значения по `b` бит, упакованы **битовыми плоскостями**: `b` слов `u32`,
    бит `i` слова `j` = бит `j` значения `i`. Единая распаковка для любого `b`,
    без пересечения границ байта (у 3/5/6 бит контиг-упаковка их пересекает).
  - Значение: `w = d·sub_scale[s]·q − dmin·sub_min[s]`, `q ∈ [0, 2^b−1]`, минимумы ≥ 0 как у
    Q4_K (асимметрично — на 2–4 битах это заметно лучше симметрии; при b=1 это две точки).
  - Размер: `32·b + 20` байт на 256 → `b + 0,625` bpw (SQ4 = 4,625, SQ2 = 2,625; Q4_K — 4,5,
    Q2_K — 2,625).
  - Требование `K % 32 == 0`, хвостовой супер-блок может быть неполным.
- **Один блоб** на тензор (шкалы внутри блока), как у ggml → `QuantWeight.scales` пустой;
  в манифесте бандла `format = "sq4"`, `"sq2"` …; в `DType` — `DType::Sq { bits: u8 }`.
- **Энкодер на GPU**: warp на супер-блок, min/max → RTN, затем перебор ~16 поправок шкалы по
  MSE (аналог `make_qkx2_quants`, но без CPU). Importance-взвешивание — не в этой версии.
- **Ядра** — через `TileDecoder<Sq<b>>`: деквант в f16-плитку для GEMM, dp4a-GEMV
  (активация в int8 по 32 со своей шкалой; веса раскладываются из плоскостей в int8 за
  `b` сдвигов-масок на 4 значения).
- Группа фиксирована (32/256): переменная группа удваивает набор инстансов ядер, а выигрыш
  в качестве против под-шкал на 32 невелик. Если нужна переменная — скажите, заложу
  `group` вторым параметром сразу.

## 3. Целочисленные форматы ggml в движке

- `DType::Ggml(GgmlType)` — вложенный вариант; `GgmlType` с `block_elems/block_bytes`
  переезжает в `synaptix-core`, `synaptix-gguf` его реэкспортирует.
- Один блоб, байт в байт как в файле → mmap `.gguf` напрямую в пиновое зеркало и на карту.
- GPU-деквант всех 31 типов (`ggml_dequant_f16`) + `TileDecoder<Ggml<T>>` для 21 типа,
  которые реально встречаются в раздачах: Q4_0/1, Q5_0/1, Q8_0, Q2_K…Q6_K, IQ1_S/M,
  IQ2_XXS/XS/S, IQ3_XXS/S, IQ4_NL/XS, TQ1_0/2_0, MXFP4. Q8_1/Q8_K — только как формат
  активаций (dp4a), как в llama.cpp.
- Тесты: GPU-деквант бит в бит с CPU-эталоном `synaptix-gguf::dequant` (расширенным на
  недостающие типы), плюс короткая сверка логитов с llama.cpp на одной Q4_0-модели из
  Downloads.

## 4. Каркас архитектур

`DeviceCaps { cc_major, cc_minor, sm_count, smem_optin, fp4_mma (sm_120/100),
mxfp8_mma (sm_100/120), fp8_mma (sm_89+), fp8_cvt (sm_89+), tma (sm_90+), bf16_mma (sm_80+),
dp4a (sm_61+) }` — один запрос на контекст. NVRTC-цель из `cc`
(`sm_120a`/`sm_100a`/`sm_90a`/`sm_89`/`sm_86`/`sm_80`), override `SYN_FORCE_ARCH` для
эмуляции. Все Blackwell-модули — `Option` с сообщением «ядро X недоступно на sm_YY,
используется путь Z». Тест: каждый `.cu` собирается под свою минимальную архитектуру
(`compute_80` для портируемых), sm_120-инструкции в них не допускаются.

## 5. Перекодировка при загрузке (Р4)

- `Transcoder`: `любой формат → f16 (на GPU) → целевой формат (GPU-энкодер)`, один вес в
  пути; направления: BF16/F16 → SQ*/NVFP4/MXFP8; ggml → SQ*/NVFP4/MXFP8; NVFP4/MXFP8 → SQ*.
- Выбор хранилища: `оценка размера ≤ свободная RAM − запас` → pinned-арена в RAM
  (`TranscodedSource: WeightSource`, диапазоны зеркала указывают в неё); иначе дисковый
  кэш `.syn` с манифестом, затем обычная загрузка. Ключ кэша — хеш bundle_id + формат.
- `optimal_profile(path, caps)`: на карте без FP4-MMA NVFP4-бандл идёт путём Р2, BF16-бандл
  по умолчанию → SQ4; GGUF — как есть (ggml-ядра), опция «в SQ». В UI — только форматы,
  исполняемые картой; предупреждение о двойном кванте при перекодировке из квантованного.

## 6. GGUF (Р5, Р10)

- Реестр мапперов по `general.architecture` (7 архитектур) вместо одного модуля; каждый
  маппер даёт имена тензоров, `config.json`, `generation_config.json`.
- Токенизатор: SentencePiece (`llama`) для Gemma/Llama-2/Mistral + таблица
  `tokenizer.ggml.pre` → регэксп (все известные значения, неизвестное — ошибка, не тихий
  Qwen) + `tokenizer.chat_templates`.
- `GgufWeightSource` поверх mmap: квант-тензоры как `QuantWeight` (ggml-формат),
  плавающие — как сейчас. `.gguf` принимают `load_llm*`, `run/chat/bench/inspect`, чат и
  ноды synthos (регистрация модели по расширению, mmproj рядом — как в HF-браузере).
- Конвертация с `OutDtype::Keep`: блоки копируются байт в байт в `.qpacked`, манифест
  `format = "<ggml-name>"`.

## 9. Риски
- Объём ~30–40 рабочих дней; этап 2 — самый дорогой, а скорость dp4a/W×A16 на реальных
  Ampere/Ada измерить не на чем. Эмуляция гарантирует корректность, не скорость.
- Качество SQ на 1–3 битах без importance-взвешивания будет ниже IQ*-форматов llama.cpp;
  это честная цена за простой формат. Замер на этапе 5 покажет, нужна ли imatrix-версия.
- Лимит smem 99 КБ на sm_86/89 сейчас соблюдён; новые ядра не должны его превышать.
- `Backend`: вместо новых `*_sq4`-методов — параметризованные по `fmt` сигнатуры; правка
  существующих 22 методов затрагивает все модели.
