# Все модели на карте 7 ГБ VRAM (2026-09-19)

Задача: любая модель из `~/Storage/syn_models` должна работать, когда модели
остаётся ~7 ГБ видеопамяти. То, что не влезает, стримится с хоста (RAM) или
из mmap бандла. Проверка — балласт в VRAM (отдельным процессом: `cudaMalloc`
всего, кроме 7 ГБ, и сон; или тензором внутри теста) и смоуки/тесты с
настоящими весами.

Скорость на малой карте упирается в PCIe: блок, которого нет на карте,
приезжает на каждом шаге. Если RAM не хватает для пиннованных копий, веса
читаются из mmap бандла (медленнее, но работает).

## Как проверять

```sh
# балласт отдельным процессом (исходник — scratchpad ballast.cu: cudaMalloc + sleep)
./ballast 7 &   # оставляет модели 7 ГБ
# чат-LLM (путь чата synthos: optimal_profile → подгонка блоков → префикс-KV)
LLM_MODEL=~/Storage/syn_models/qwen3.8-27b.syn LLM_VRAM_GB=7 \
  cargo test -p synaptix --release --test llm_low_vram -- --nocapture
# FLUX.2 через ноды synthos
FLUX2_VRAM_GB=7 cargo run --release --bin flux2_smoke -- ~/Storage/syn_models/flux.2-klein-4b.syn out.png 1024 1024
# музыка с резидентным кэшем, как «Держать в памяти» у нод
synaptix music "…" --models ~/Storage/syn_models --lm …/acestep_5hz_lm_4b.syn --quant none --quant-encoder none --repeat 2
```

`llm_low_vram` печатает минимум свободной VRAM за прогон; `flux2_smoke`,
`ltx_smoke`, `h3_smoke` — по стадиям.

## Что изменено в synaptix

- **Общий декодер LLM** (`llm/common/model.rs`): при оффлоаде блоков
  (`build_auto` не уложился в VRAM) таблица эмбеддингов живёт в RAM, строки
  выбираются на хосте (`embed_host`); графовые пути с ней выключаются. MoE в
  оффлоаде держит блоки на карте, а экспертов — в RAM с общим `ExpertCache`,
  ёмкость которого подгоняется под префилл/декод (`fit_expert_cache`). Между
  попыткой «всё на карте» и оффлоадом отдаются все пулы.
- **Gemma-4** грузится через `build_auto` (раньше — всегда целиком на карту).
- **Qwen4Exp**: эмбеддинги в RAM на карте < 16 ГБ, чанк префилла 256 на
  малой карте.
- **VibeVoice**: слои LM стримятся (`Qwen2Model::for_each_layer`), таблицы
  эмбеддингов и головы — в RAM (генерации нужны только строки).
- **ACE-Step LM**: `build_auto`, веса читаются туда, куда просит декодер
  (раньше всё шло на карту и в оффлоаде); на время AR часть блоков
  возвращается на карту (`AceStepLm::fit_blocks`/`restore_blocks`); графовый
  AR — только при полной резидентности.
- **Арена TMA-дескрипторов** (`synaptix-kernels-cuda/tma.rs`): дескриптор из
  захваченного CUDA-графа закрепляется навсегда — раньше кэш BF16-GEMM
  сбрасывался на 512 записях, слот уходил в оборот, и граф денойза ACE-Step
  падал `CUDA_ERROR_ILLEGAL_INSTRUCTION`. Теперь граф ACE-Step работает и
  совпадает с обычным путём бит в бит, но остаётся опциональным
  (`SYN_ACESTEP_GRAPH=1`): он не быстрее.
- **`compute_stream_for`**: ядро, запущенное из самого потока префетча,
  ждёт loader-стрим (защитная правка; синтетикой гонку не воспроизвести —
  cudarc и так ставит ожидание по событию записи).
