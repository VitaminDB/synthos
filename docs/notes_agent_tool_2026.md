# Инструмент `notes` — доступ агента к «Заметкам» (2026-09)

Агент Syn-чата (и субагенты) получил полный API режима «Заметки»: дерево
страниц, markdown страниц, блоки с координатами и стилями, фигуры и
стрелки, раскладка холста, канбан-доски, диаграммы Ганта, интеллект-карты,
календари с событиями проекта, вложения.
Инструмент работает с тем же проектом `.syn` и теми же ручками, что и UI
(`NotesCtx`), поэтому правки видны в интерфейсе сразу, уходят на диск
автосейвом и отменяются пользователем через Ctrl+Z, как свои.

Код: `src/agent/tools/notes.rs`; описание для модели — `catalog.rs`
(`KEY_NOTES`, схема собирается функцией `notes_schema()` — один `json!`
на сорок свойств упирается в лимит рекурсии макроса); правила поведения —
блок «Notes» в `syn_chat::system_prompt`, включается только при активном
инструменте (текст промпта зависит лишь от набора инструментов — префикс-KV
между сообщениями не страдает). Инструмент входит в стартовый набор
(`config::default_tools_active`); в существующих конфигах включается
чипом в правой панели чата.

## Действия

| action | Аргументы | Что делает |
|---|---|---|
| `list` | — | дерево страниц: id, название, иконка, объём в словах, объекты на странице (`kanban:<id>`, `gantt:<id>`); файл проекта, активная страница |
| `search` | `query`, `limit` | поиск без регистра по названиям и тексту, до четырёх совпавших строк на страницу |
| `read` | `page` / `pages`, `depth`, `blocks`, `limit` | markdown страницы, строка раскладки (`layout · grid · snap`), доски и диаграммы на ней (с id карточек и задач), ссылки; `blocks=true` — секция блоков с индексами, координатами и атрибутами. **Массово:** `pages: [id, id]`, `depth=all` (страница с поддеревом), `page="all"` (весь проект) |
| `create` | `title`, `parent`, `index`, `content`, `icon`, `layout`, `grid`, `grid_step`, `snap`, `snap_step`, `open` | новая страница (название уникально среди соседей), тихо — пользователя с его страницы не уводит |

Карточка: `title`, `md` (чек-лист `- [ ]` даёт прогресс), `priority`
`low|medium|high|urgent|none`, `tags` (массив или через запятую), `due`
`yyyy-mm-dd|today|tomorrow|none`, `before` (перед какой карточкой),
`column` (переезд). Цвет колонки/задачи — `#rrggbb` или
`gray|orange|green|blue|purple|red|teal` (палитра `kanban::model::PALETTE`);
фоны доски и блоков принимают ещё `#rrggbbaa`.

Узел карты — id, точный текст либо `root`; событие — id или заголовок
(при совпадениях уточняется `on: <дата>`); календарь — id или название.
Карта: `outline` строит дерево из markdown (заголовок или первый абзац —
корень, вложенные списки — узлы, `- [x]` даёт иконку ✓), `read` печатает
дерево с отступами, `style` принимает `palette` (имя пресета
`theme|rainbow|pastel|mono` либо список цветов), цвета узлов и линий,
кегль, скругление, отступ, толщину и пунктир линий, фон, иконки.
Календарь: события живут в **общем хранилище проекта**
(`notes/calendar.json`), виджет на странице — только вид, якорь, фильтр
календарей и стиль; `delete` убирает виджет, события остаются.
`start_time`/`end_time` — `HH:MM` в локальном времени, `start_time=none`
делает событие «весь день»; перенос даты тянет за собой конечную дату
многодневного события. `include_external=true` добавляет в вывод сроки
карточек досок и задачи Ганта проекта (read-only слой виджета).

Атрибуты блока (`blocks op=set_attrs`, проверяются теми же диапазонами, что
панель свойств): текст — `color bg size(6..160) weight(bold|normal)
align(left|center|right)`; геометрия — `x y w(≥40) h(≥20)`; фигуры — `fill
stroke(#|none) sw(0..40) dash(0..60) radius(0..200) opacity(0..100)`; концы
линий — `x1 y1 x2 y2 cx1 cy1 cx2 cy2` (относительно блока; удобнее
`shape op=update` с абсолютными точками). Линейная фигура держится в каноне:
минимум точек в нуле, рамка сдвинута под них, `w/h` — bbox плюс поле
`LINE_PAD` (`canonicalize_line` / `set_line_points`). `connect` берёт точку
на середине стороны прямоугольника блока (`x y w`, `h` — из атрибута либо
оценка `est_height`), сторона `auto` — обращённая к другому блоку.

## Массовое чтение

Локальная модель платит за каждый вызов инструмента целым ходом: новый
префилл промпта, генерация, разбор. Чтение «по странице» (а тем более «по
блоку») превращало обход дерева заметок в десятки ходов и минуты
ожидания — 07.09.2026 пользователь получил ровно это. Поэтому `read`
берёт сразу пачку:

- `pages: ["<id>", "Название", …]` — произвольный список страниц; строку
  через запятую тоже принимает, но целая строка важнее (в названии
  страницы запятая законна — `resolve_many`).
- `depth` — сколько уровней подстраниц добрать к каждой запрошенной
  странице: `0` (по умолчанию — только она), `1` — дети, `all`/`true`/
  отрицательное — всё поддерево (`depth_arg`, `subtree_within`).
- `page: "all"` (`*`, `project`, `everything`) — весь проект; ключевое
  слово срабатывает, только если такой страницы в проекте нет.
- `limit` — верхняя граница числа страниц в ответе.
- `blocks=true` работает вместе с ними: одним вызовом возвращается всё
  поддерево с геометрией блоков.

Порядок — как в дереве (DFS), повторы убираются. Одна страница отвечает
ровно как раньше (формат ответа не изменился), пачка — с шапкой
`--- N pages · M words · all of them in this reply ---` и разделителями
`=== page k/N ===`.

Ответ ограничен `READ_BUDGET` = `MAX_OUTPUT_BYTES − 8 KB`: исполнитель
режет вывод инструмента на 64 KB молча и посреди строки, поэтому чтение
останавливается само — на границе страницы — и печатает секцию
`--- Not read (k) ---` со списком id и подсказкой дочитать их одним
следующим вызовом. Первая страница входит в ответ всегда, даже если одна
превышает бюджет.

Одиночное чтение страницы, у которой есть дети, заканчивается секцией
`--- Sub-pages (N) — read the whole subtree in ONE call with depth=all ---`
со списком id, объёмов и числа детей: без неё модель узнаёт о подстранице
только из `list` и идёт за ней отдельным ходом.

`blocks op=read` устроен так же: `block` принимает `all`/`*`, список
индексов и диапазонов (`"0,2,5-7"`), массив ссылок или одну ссылку
(индекс либо `find:<текст>` — прежний формат ответа). Разбор —
`resolve_block_list`; текстовые ссылки от списка индексов отличаются
тем, что список состоит только из цифр, `#`, `,` и `-`.

Правило для модели живёт в трёх местах: описание инструмента и схема
(`catalog.rs` — `pages`, `depth`, обновлённые `page`, `block`, `limit`,
`blocks`), блок «Notes» системного промпта («Read in bulk, not page by
page») и хвост ответа `list`.

## Адресация

- **Страница** — id (12 hex) либо название без регистра; при совпадениях —
  путь `Родитель / Страница` или id (ошибка перечисляет кандидатов с путями).
- **Доска / диаграмма** — id объекта (`kanban:<id>` из `list`/`read`) либо
  страница, где объект один; без `board`/`chart` и `page` — единственный
  объект проекта, иначе ошибка со списком.
- **Колонка** — id, название или номер с единицы; **карточка / задача** —
  id или заголовок (неоднозначный заголовок — ошибка со списком id).
- **Узел карты** — id, точный текст либо `root`; **событие** — id или
  заголовок (`on` уточняет дату); **календарь** — id или название.
- **Блок** — индекс верхнего уровня из `blocks op=list` / `read blocks=true`
  (`3`, `#3`, число) либо `find:<фрагмент>` — единственное вхождение в
  markdown блока (иначе ошибка со списком индексов). Персистентных id у
  блоков нет; правило промпта — перечитать список после вставки/удаления.

Каждый ответ, касающийся страницы, содержит строку
`page: <id> · "Название" · path: …`: по ней модель берёт id для следующих
вызовов, а пузырь чата (`message_bubble::open_notes_link`) рисует ссылку
«Открыть в заметках» (`chat.msg.notes.open_page`) — она открывает плитку
проекта и активирует страницу.

## Служебный хвост: геометрия и стили

Координаты блоков (`x y w h`) и — у блоков без места под инлайн-атрибуты
(абзац, списки, код, таблица, разделитель) — все их свойства (`color bg
size align weight`) живут в хвостовом служебном блоке ```` ```doc-layout ````
markdown'а по *индексу* блока (`free::sidecar_attrs`). Агенту показывать
его нельзя (вставит абзац — индексы съедут) и править им — тоже. Поэтому
агент видит **плоскую форму** (`plain_markdown`: `strip_sidecar` снимает с
блока ровно то, что ушло бы в хвост, модель сериализуется обратно), а при
записи целиком (`mode=replace`, `create content`) `with_sidecar` парсит
старый и новый текст и переносит **все** атрибуты на блоки, чей markdown не
изменился (совпадение по `block_markdown`, по порядку, каждый старый блок —
один раз). Переставленный или вставленный абзац не сбивает ни холст, ни
оформление; переписанный блок атрибутов не получает и встаёт в колонку
потока — как в UI при вставке.

Точечные правки идут **по модели**, а не по тексту: `find`/`replace`
ищет фрагмент внутри `block_markdown` одного верхнеуровневого блока и
перепарсивает только его (`replace_in_blocks`; первый новый блок наследует
атрибуты старого; фрагмент через границу блоков — ошибка с советом взять
`blocks op=set_markdown`), а `blocks`/`shape` правят `DocModel` напрямую и
пишут `serialize_document` через тот же `set_page_markdown` — отмена у
пользователя работает как обычно. Очередь `DocOp` инструмент не использует:
её применяет только смонтированный редактор, а агент правит и закрытые
страницы. Удаление объекта убирает врезку `![[kind:id]]` на уровне модели
(`remove_embed`, включая вложенные блоки), геометрия остальных сохраняется.

Высоту текстового блока модель не знает — в `blocks op=list` она печатается
оценкой `h=~N` (`est_height`: по числу строк и ширине, у таблицы по строкам,
у кода по строкам); её же берёт `connect` для стороны прямоугольника.

## Как это ложится на состояние UI

- `NotesCtx::set_page_markdown` — единственная точка записи текста:
  `DocumentEditorHandle::replace_markdown` (syngui) заменяет модель с
  checkpoint'ом в истории, ставит отпечаток исходника на новый текст и
  бампает ревизию; исходник в пуле `pages` обновляется на тот же текст —
  иначе первый показ страницы, которую ни разу не открывали, перепарсил бы
  старый исходник поверх правки агента. Смонтированный редактор
  перестраивается по `doc_epoch`, а `clear_rebuild` элемента снимает
  каретку и выбор с исчезнувших блоков. Индекс связей обновляется сразу.
- `insert_page(parent, index, title, activate=false)` и
  `duplicate_page_with(id, false)` — создание без активации (UI по-прежнему
  активирует). Удаление — общий `delete_page`.
- Доски и диаграммы правятся через `KanbanHandle`/`GanttHandle` (`edit`
  бампает `revision` → автосейв и перестройка вида); новая карточка
  кладётся `insert_card`, а не `add_card` — тот открывает правку на месте.
  Удаление объекта — `NotesCtx::delete_object` (файл из бандла ближайшим
  коммитом, ручка из пула) после чистки врезок.
- Всё исполняется на main-потоке внутри `run_on_main_thread` (сигналы
  thread-local), результат — через oneshot; `dispatch(ctx, action, args)`
  вынесен отдельно, чтобы тесты звали его на своём `NotesCtx` над
  временным проектом.

## Геометрия свободной раскладки (07.09.2026)

Корень «страницы-каши»: на free-странице блок без `x`/`y` рисуется в
колонке потока по центру холста **поверх** закреплённых, а модель координат
не видит и надеется, что редактор разложит сам. Переключатель «Свободная
раскладка» и `create layout=free` давали страницу, где не закреплён ни один
блок. Важно: новая страница — холст по умолчанию (`PageLayout::default()`
= `free: true`), но пока на ней ничего не закреплено, она рисуется одной
колонкой и выглядит как документ; каша начинается со СМЕСИ закреплённых и
незакреплённых блоков. Поэтому агент закрепляет блоки только при явном
намерении (`layout=free` в `create`, переход поток → холст), а подсказка
`!! free layout` появляется только при смеси. Сделано:

- **Переход поток → холст сохраняет расположение.** В редакторе syngui
  (`DocumentEditor::pin_flow_blocks`, вызывается из `update` при смене
  `layout.free` false → true) каждый незакреплённый верхнеуровневый блок
  получает координаты и ширину своего прямоугольника из прошлой раскладки —
  картинка не меняется, правка попадает в историю (Ctrl+Z). У агента то же
  делает `pin_flow_blocks` в `apply_layout_args` (колонка по оценке высот:
  x=40, y=40, w=520, зазор 24) и в `create` после записи контента на
  free-странице. Обратный переход ничего не трогает: поток координаты
  игнорирует, при повторном включении холста они снова в силе.
- **`blocks op=arrange`** — одна команда вместо N вызовов `pin`: кладёт
  неприкреплённые блоки колонкой под нижним закреплённым (или все при
  `only=all`), параметры `x y w gap`. Объекты без своей высоты (фигуры,
  медиа, врезки) получают `h` по оценке, чтобы редактор и агент считали одно
  и то же. В ответе — новые прямоугольники и `the column ends at y=…`.
- **Предупреждение о наложении.** `pin` / `move` / `insert` с геометрией /
  `set_attrs` / `shape create|update` дописывают к строке блока
  `!! overlaps #3 (x=… y=… w=… h=…)`, если рамка пересекает другой
  закреплённый блок. Не запрет — подсказка: высоты текста оценочные. Линии
  не в счёт: стрелка между блоками пересекает оба по замыслу.
- Подсказка `!! free layout: N of M blocks have no x/y …` в каждом ответе по
  free-странице, пока геометрия не проставлена (`free_layout_hint`), и
  абзац LAYOUT в описании инструмента (`catalog.rs`).

Тесты: `switching_to_free_layout_pins_blocks_in_a_column`,
`arrange_stacks_blocks_and_overlaps_are_reported` (notes.rs); syngui —
`switching_to_free_layout_pins_blocks_where_the_flow_put_them`.
