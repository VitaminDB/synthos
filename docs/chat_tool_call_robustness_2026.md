# Syn-чат: вырожденные вызовы инструментов — разбор и правки (03.09.2026)

Разбор по сохранённому чату `~/.config/synthos/syn_chats/18d1703d39952280.json`
(«Redmi 9C», qwen3.8-27b, per-chat `temperature = 0.0`, `enable_thinking =
false`, `repeat_penalty = 1.05/64`) и журналу
`~/.local/state/synthos/logs/synthos.2026-09-03.log`, плюс два старых чата
с той же картиной: `18cffc50545d8e60` (28.08, ZTE, та же модель) и
`18d14395f95b735c` (02.09, flash-next).

## Симптом

Вопрос про разблокировку загрузчика Redmi 9C. DDG отдавал капчу на каждый
поиск (выходной IP), reddit и XDA закрывались JS-проверкой. Модель повторила
`web read` → guard повторов → с хода 11 «анти-loop сэмплинг». Ровно с этого
хода вызовы вырождаются, а проза внутри параметров остаётся осмысленной:

| Ходы | Режим | Токенов за ход | Что дошло до парсера |
| --- | --- | --- | --- |
| 0–10 | temp 0, без штрафов | 45–69 | корректные `web` |
| 11 | temp 0.6, freq_penalty 0.25, окно 256 | 459 | `subagent {"tasks":"\n","tools":["bash"]}` |
| 12 | то же | 455 | `task` с мусором `>\n\n\n</invoke>>`, `tools` строкой |
| 13–14 | то же | 307 | только `tools`, второй раз тот же → guard |
| 15–17 | то же | 251–283 | `bash {}` три раза → стоп |

Разрыв между числом сгенерированных токенов и размером разобранных
аргументов показывает, что парсер терял тело вызова; сырой вывод модели
нигде не сохранялся.

В чате 28.08 после того же анти-loop режима модель написала
`<invoke name=bash">` без открывающей кавычки — инструмент стал называться
`bash"`, и дальше 25 ходов чередовались `bash" {}` и
`bash {"arguments":"\n\n\n"}`; guard «три одинаковых подряд» чередование не
ловил. Там же в хвосте текстового ответа утёк «user» вместо `im_end`.
В чате 02.09 без штрафов вовсе модель передала `arguments` строкой с
экранированным JSON.

## Корень

Frequency-штраф (аддитивный, `−0.25 · count` по окну в 256 токенов) бьёт по
самым частым токенам вызова инструмента: кавычкам, переводам строк, `>`,
скобкам. У структурного токена нет синонима, и модель подменяет его редким
вариантом: `>>`, `\r\n`, `\n\n\n`, пропущенная кавычка, `</invoke>` вместо
`</parameter>`, XML-стиль вместо JSON (в нём меньше кавычек). Тот же режим
растягивал окно `repeat_penalty` пользователя с 64 до 256 токенов. Greedy-декод
(temp 0) сам по себе даёт повторы (Qwen его прямо не рекомендует), повтор
включает guard, guard включал штрафы — и синтаксис ломался.

KV-путь гибрида проверен чтением (facade/llm.rs, common/model.rs,
gated_delta_net.rs, qwen3_next_hybrid/pipeline.rs): `reusable()` сверяет токены
побайтно и требует полного префикса; точка возврата кратна 64 со снимком
host+dev; при reuse 0 состояние GDN обнуляется вместе с device-зеркалами;
парковка в RAM вокруг субагента сбрасывает зеркала и пересеивает их из host;
MTP-reject восстанавливает linear-состояние из пошагового снимка; контекст
сэмплера в стохастическом MTP-пути ведётся консистентно. Ошибок не найдено.

Отдельный дефект по KV, не связанный с порчей: история, собранная из ленты на
следующем сообщении, не совпадала с историей хода — результаты инструментов
шли без клипа в 8000 символов, заметки хода (`[Системная заметка…]`,
budget_note, `EMPTY_TURN_NOTE`) в ленте отсутствовали, а реплика ассистента с
вызовом в ходе была сырым текстом модели, в пересборке — каноническим JSON
(причём `serde_json::json!` без `preserve_order` ставил `arguments` перед
`name`). Итог: «префикс-KV переиспользовал 0 из N» на каждом новом сообщении
(28.08: 0/58044 → 57 с префилла; 0/11293 → 7,6 с; 0/13645 → 9,5 с).

## Что сделано

- **Анти-loop сэмплинг** (`syn_chat::session`): только подъём температуры до
  0.6, без frequency-штрафа и без растягивания окна; режим снимается первым
  же неповторённым вызовом.
- **Guard чередования**: период-2 петля `A B A B` — предупреждение (вызов
  пропущен, модели подсказка), `A B A B A B` — остановка хода. Состояние
  восстанавливается из ленты, как и у guard'а повторов.
- **Серия невалидных аргументов**: три вызова подряд, не прошедших разбор
  аргументов (`ToolOutcome::invalid_args`), останавливают ход с внятной
  причиной вместо сгорания бюджета ходов.
- **Парсер** (`syn_chat::tool_parser`): `arguments` строкой с JSON,
  вложенный `{"arguments": {...}}`, пустая заглушка `"arguments": "\n\n"`
  рядом с настоящими полями и параметры рядом с `name` без обёртки —
  разворачиваются во всех трёх форматах. Пустые аргументы (`{}`) пишутся в
  журнал с сырым телом блока (WARN), XML-стиль — INFO.
- **История и лента**: результаты из ленты клипаются тем же
  `clip_for_history`; заметки хода хранятся скрытым полем
  `ChatMsg::model_note`; заметка после пустого хода живёт один ход
  (`pending_note`), а не в истории; реплика ассистента с вызовами строится
  одной функцией `tool_turn_text` (`{"name": …, "arguments": …}` в порядке
  шаблона Qwen) и в ходе, и в пересборке из ленты, текст перед вызовом
  сливается с ним в одну реплику.
- **Дефолты сэмплинга** (`syn_chat::params`): рекомендованные Qwen 0.6 / 0.95 /
  20 без штрафа за повторы; конфиг с ровно старым набором мигрирует
  одноразово (`AppConfig::migrate_sampling_defaults`), изменённые значения и
  per-chat параметры не трогаются.
- **Поиск** (`agent::tools::web::search`): после DDG html и lite — Bing
  (SSR-выдача, редирект `/ck/a?…&u=a1<base64url>` распаковывается); шапка
  envelope'а показывает, чей результат (`engine=bing`).
- **Время в ленте**: локальное смещение через `localtime_r` вместо UTC.
- **Headless-раннер** `src/bin/agent_smoke.rs`: настоящий `send_message` на
  реальной модели без окна, несколько сообщений подряд, вердикт по ленте.

## Как проверять

```
cargo test -p synthos --lib -- syn_chat::tool_parser syn_chat::session \
    syn_chat::params config::tests agent::tools::web
cargo build --release -p synthos --bin agent_smoke
SYN_SMOKE_OUT=/tmp/ledger.json target/release/agent_smoke \
    /home/master/Storage/syn_models/qwen3.8-27b.syn "<вопрос>" "<уточнение>"
```

В журнале: строка «анти-loop сэмплинг: temp=…» без штрафов, «guard
повторов … чередуется», «guard аргументов», «tool_call без аргументов» с
сырым телом, «префикс-KV переиспользовал N из M» на втором сообщении.
