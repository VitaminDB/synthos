# Визард опроса в чате (08.09.2026)

Инструмент агента `wizard`: модель задаёт пользователю вопрос с
вариантами, в ленте появляется панель с кнопками, клик уходит обычным
сообщением пользователя, а ход агента на вызове заканчивается.

## Формат вызова

```json
{
  "question": "Какой период выбрать?",
  "options": [
    {"label": "Неделя", "value": "week"},
    {"label": "Месяц", "value": "month", "tooltip": "30 дней"},
    {"label": "Свой", "allow_free_text": true}
  ],
  "allow_multiple": false,
  "allow_free_text": false,
  "required": true,
  "timeout_sec": 300
}
```

`agent::tools::wizard::parse_spec` нормализует аргументы: пустые подписи
выбрасываются, больше 12 вариантов — ошибка, без вариантов панель
становится полем свободного ответа, `timeout_sec: 0` — без таймера.
Ответ инструмента модели — стабильная строка от аргументов («The question
is shown… Your turn ends here… one of: A | B»): префикс-KV требует, чтобы
лента и промпт совпадали байт в байт.

## Как заканчивается ход

`session::run_agent_loop`: после результата вызова `wizard` (пара
call/result уже в ленте и в `history`) взводится `awaiting_user`; когда
все вызовы этого хода исполнены, `answered = true; break 'agent` —
пустой плейсхолдер следующего хода не ставится, «Продолжить» не
предлагается. Ответ пользователя приходит следующим сообщением и модель
видит его в контексте как обычную реплику. Подтверждение инструмента
(`tool_flow::await_decision_on_tool_call`) для визарда не спрашивается:
вопрос — не действие. Субагенту визард не выдаётся (`subagent.rs`): у него
нет ленты.

Правила в системном промпте (`system_prompt.rs`, блок «Wizard», только при
активном инструменте): когда пользоваться, что вызов ЗАКАНЧИВАЕТ ход,
одна панель — один вопрос, 2–6 коротких вариантов.

## Панель в ленте

`pages::syn_chat::wizard` — рендер tool_call-сообщения с `tool_name ==
"wizard"` в любом режиме показа инструментов (`message_bubble::view`);
результат вызова прячется, под шапку группы инструментов панель не
попадает (`message_area::pair_at`). Спецификация читается из аргументов
вызова; если она не разбирается — обычная карточка инструмента.

- вопрос рисуется той же `MarkdownView`, что ответ ассистента
  (`message_bubble::bubble_markdown`, классы `msg-bubble-md
  wizard-question-md`): код с подсветкой, списки, жирный. В свёрнутой
  панели — первая строка без разметки (`question_summary`);
- одиночный выбор — кнопки `.wizard-option`, клик отправляет сразу;
  короткие подписи — в строку с переносом (`Flex::row().wrap()`),
  если хоть одна длиннее `WIDE_LABEL_CHARS` (36) — столбиком на всю
  ширину (`.wizard-option-wide`); вариант с `allow_free_text` открывает
  поле, ответ «Подпись: текст»;
- множественный — чипы-флажки `.wizard-chip` (иконка check_box /
  check_box_outline_blank) и «Отправить» (подписи через запятую);
- `allow_free_text` панели — поле всегда видно, Enter отправляет;
- `required` — нет «Пропустить»; иначе «Пропустить» сворачивает панель,
  ничего не отправляя;
- `timeout_sec` — обратный отсчёт в подвале и полоса остатка времени
  (`ProgressBar.wizard-timer-bar`) над ним; последние 10 с — цветом
  `--warning`; по сроку панель сворачивается с пометкой «Время вышло»,
  ничего не отправляя.

Карточка — форма стабильной ширины (`max-width: 640px`), не пузырёк:
`Flex` с переносом и `Column` со `Stretch` занимают всю доступную ширину,
так что при любых вариантах карточка одинаковая. Подвал отделён тонкой
линией (`.wizard-footer`, `border-top-width`).

## Подсветка кода в вопросе (08.09, вторая итерация)

Изначально вопрос рисовался `Text` — код из вопроса-теста шёл сырым
текстом без моноширинного шрифта и подсветки. Теперь — `MarkdownView`.
Но модель писала код отступом (indented code block) — без метки языка
syntect подсвечивать нечего. Два шага:

- `syngui::widgets::visual::markdown_view::highlight::guess_language` —
  догадка о языке по маркерам (rust, python, javascript, json, bash, html,
  sql, cpp, go, css) с порогом и отрывом от второго кандидата; применяется
  в `pick_syntax`, когда метки нет или она незнакома. Обычный текст, список
  файлов, лог остаются без подсветки (тесты `guess_tests`). Работает для
  всех блоков без метки — и в ответах ассистента, и в выводе инструментов;
- описание `question` в схеме инструмента и блок «Wizard» системного
  промпта просят фенс с меткой языка (```rust … ```), не отступ.

Ответом считается любое сообщение в ленте после результата вызова —
тогда панель свёрнута в строку «вопрос · Отвечено». Текст ответа —
`answer_text` (подписи, не `value`: модель сама писала соответствие).

Состояние панели — `SynChatCtx::wizard_drafts` (`WizardDraft`) по индексу
сообщения: сигнал внутри ленты пересоздавался бы при каждом её ребилде.
Панель — своя `Reactive` на черновики и на `wizard_tick`, поэтому секундный
отсчёт не перестраивает ленту. Таймер ставится при первом показе живой
панели следующим тиком main-thread (не из сборки ленты); черновики
сбрасываются при смене чата и очистке ленты — вернувшись в чат,
пользователь получает отсчёт заново. Стили — `styles/components/wizard_panel.mss`.

## Что проверено

Первый прогон с моделью (08.09, Rust-тест с кодом в вопросе): панель
работает, клик уходит сообщением, ход заканчивается. Юниты:
`agent::tools::wizard::tests`, `pages::syn_chat::wizard::tests`
(`question_summary`), `config::tests::wizard_tool_is_introduced_once`,
`system_prompt::tests::wizard_rules_only_with_wizard_tool`, стражи
схемы/i18n/MSS, `guess_tests` в syngui.

Не проверено живьём после второй итерации: новая раскладка (перенос
кнопок, столбик длинных подписей, полоса таймера) и подсветка догадкой
в GUI — только компиляция и юниты.
