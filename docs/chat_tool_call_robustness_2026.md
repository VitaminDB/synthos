# Syn-чат: вырожденные вызовы инструментов — разбор и правки (03.09.2026)

Разбор по сохранённому чату `~/.config/synthos/syn_chats/18d1703d39952280.json`
(«Redmi 9C», qwen3.8-27b, per-chat `temperature = 0.0`, `enable_thinking =
false`, `repeat_penalty = 1.05/64`) и журналу
`~/.local/state/synthos/logs/synthos.2026-09-03.log`, плюс два старых чата
с той же картиной: `18cffc50545d8e60` (28.08, ZTE, та же модель) и
`18d14395f95b735c` (02.09, flash-next).

## Симптом

Вопрос про разблокировку загрузчика Redmi 9C. DDG отдавал капчу на каждый
поиск (выходной IP), reddit и XDA закрывались JS-проверкой. Модель повторила
`web read` → guard повторов → с хода 11 «анти-loop сэмплинг». Ровно с этого
хода вызовы вырождаются, а проза внутри параметров остаётся осмысленной:

| Ходы | Режим | Токенов за ход | Что дошло до парсера |
| --- | --- | --- | --- |
| 0–10 | temp 0, без штрафов | 45–69 | корректные `web` |
| 11 | temp 0.6, freq_penalty 0.25, окно 256 | 459 | `subagent {"tasks":"\n","tools":["bash"]}` |
| 12 | то же | 455 | `task` с мусором `>\n\n\n</invoke>>`, `tools` строкой |
| 13–14 | то же | 307 | только `tools`, второй раз тот же → guard |
| 15–17 | то же | 251–283 | `bash {}` три раза → стоп |

Разрыв между числом сгенерированных токенов и размером разобранных
аргументов показывает, что парсер терял тело вызова; сырой вывод модели
нигде не сохранялся.

В чате 28.08 после того же анти-loop режима модель написала
`<invoke name=bash">` без открывающей кавычки — инструмент стал называться
`bash"`, и дальше 25 ходов чередовались `bash" {}` и
`bash {"arguments":"\n\n\n"}`; guard «три одинаковых подряд» чередование не
ловил. Там же в хвосте текстового ответа утёк «user» вместо `im_end`.
В чате 02.09 без штрафов вовсе модель передала `arguments` строкой с
экранированным JSON.

## Корень

Frequency-штраф (аддитивный, `−0.25 · count` по окну в 256 токенов) бьёт по
самым частым токенам вызова инструмента: кавычкам, переводам строк, `>`,
скобкам. У структурного токена нет синонима, и модель подменяет его редким
вариантом: `>>`, `\r\n`, `\n\n\n`, пропущенная кавычка, `</invoke>` вместо
`</parameter>`, XML-стиль вместо JSON (в нём меньше кавычек). Тот же режим
растягивал окно `repeat_penalty` пользователя с 64 до 256 токенов. Greedy-декод
(temp 0) сам по себе даёт повторы (Qwen его прямо не рекомендует), повтор
включает guard, guard включал штрафы — и синтаксис ломался.

KV-путь гибрида проверен чтением (facade/llm.rs, common/model.rs,
gated_delta_net.rs, qwen3_next_hybrid/pipeline.rs): `reusable()` сверяет токены
побайтно и требует полного префикса; точка возврата кратна 64 со снимком
host+dev; при reuse 0 состояние GDN обнуляется вместе с device-зеркалами;
парковка в RAM вокруг субагента сбрасывает зеркала и пересеивает их из host;
MTP-reject восстанавливает linear-состояние из пошагового снимка; контекст
сэмплера в стохастическом MTP-пути ведётся консистентно. Ошибок не найдено.

Отдельный дефект по KV, не связанный с порчей: история, собранная из ленты на
следующем сообщении, не совпадала с историей хода — результаты инструментов
шли без клипа в 8000 символов, заметки хода (`[Системная заметка…]`,
budget_note, `EMPTY_TURN_NOTE`) в ленте отсутствовали, а реплика ассистента с
вызовом в ходе была сырым текстом модели, в пересборке — каноническим JSON
(причём `serde_json::json!` без `preserve_order` ставил `arguments` перед
`name`). Итог: «префикс-KV переиспользовал 0 из N» на каждом новом сообщении
(28.08: 0/58044 → 57 с префилла; 0/11293 → 7,6 с; 0/13645 → 9,5 с).

## Что сделано

- **Анти-loop сэмплинг** (`syn_chat::session`): только подъём температуры до
  0.6, без frequency-штрафа и без растягивания окна; режим снимается первым
  же неповторённым вызовом.
- **Guard чередования**: период-2 петля `A B A B` — предупреждение (вызов
  пропущен, модели подсказка), `A B A B A B` — остановка хода. Состояние
  восстанавливается из ленты, как и у guard'а повторов.
- **Серия невалидных аргументов**: три вызова подряд, не прошедших разбор
  аргументов (`ToolOutcome::invalid_args`), останавливают ход с внятной
  причиной вместо сгорания бюджета ходов.
- **Парсер** (`syn_chat::tool_parser`): `arguments` строкой с JSON,
  вложенный `{"arguments": {...}}`, пустая заглушка `"arguments": "\n\n"`
  рядом с настоящими полями и параметры рядом с `name` без обёртки —
  разворачиваются во всех трёх форматах. Пустые аргументы (`{}`) пишутся в
  журнал с сырым телом блока (WARN), XML-стиль — INFO.
- **История и лента**: в ленту уходит копия результата, уже уложенная в
  окно (`fit_for_prompt`, с 07.09.2026 — по токенам вместо статического
  клипа в 8000 символов), и пересборка берёт её как есть; заметки хода
  хранятся скрытым полем
  `ChatMsg::model_note`; заметка после пустого хода живёт один ход
  (`pending_note`), а не в истории; реплика ассистента с вызовами строится
  одной функцией `tool_turn_text` (`{"name": …, "arguments": …}` в порядке
  шаблона Qwen) и в ходе, и в пересборке из ленты, текст перед вызовом
  сливается с ним в одну реплику.
- **Дефолты сэмплинга** (`syn_chat::params`): рекомендованные Qwen 0.6 / 0.95 /
  20 без штрафа за повторы; конфиг с ровно старым набором мигрирует
  одноразово (`AppConfig::migrate_sampling_defaults`), изменённые значения и
  per-chat параметры не трогаются.
- **Поиск** (`agent::tools::web::search`): после DDG html и lite — Bing
  (SSR-выдача, редирект `/ck/a?…&u=a1<base64url>` распаковывается); шапка
  envelope'а показывает, чей результат (`engine=bing`).
- **Время в ленте**: локальное смещение через `localtime_r` вместо UTC.
- **Headless-раннер** `src/bin/agent_smoke.rs`: настоящий `send_message` на
  реальной модели без окна, несколько сообщений подряд, вердикт по ленте.

Итог после всех правок (04.09.2026, бюджет 12–24 хода на сообщение):

Три случая, когда префикс обнуляется штатно и это видно в журнале: первый ход
диалога, рост KV-ринга (кэш пересоздаётся под больший размер) и автокомпакт
внутри хода (после сжатия история другая). Остальные ходы переиспользуют всё.

До правок в тех же прогонах: flash-next — «0 из N» на каждом ходу (+8 с
префилла), Muse — инструменты только в первом сообщении, дальше три из
четырёх сообщений упирались в guard повторов без единого ответа.

Единственное, что осталось за моделью: Muse путается в собственной разметке
параметров (`<atem:parameter name="web">action>search` вместо `name="action"`),
трижды подряд получает «Missing required field» и останавливается новым
guard'ом аргументов — вместо прежнего сжигания всего бюджета ходов.

Найдено и исправлено по ходу прогонов:

- `arguments`-строка с лишней `}` в конце (`{"command":"…"}}`) не
  разворачивалась — строгий JSON падал. Теперь `lenient_json`: строгий
  разбор → первое целое значение с отброшенным хвостом → починка скобок.
- **Канальный шаблон (Muse) в истории из ленты.** `build_history` рендерил
  вызовы как `<tool_call>`-JSON и для Muse; со второго сообщения модель
  копировала этот текст как обычный ответ, и инструменты не вызывались.
  Теперь `build_history` получает флаг канального режима и собирает ATEM-блок
  через `channel_parser::rebuild_turn_text`.
- **Субагент на канальной модели** разбирал только ChatML: ATEM-вызовы Muse
  не исполнялись, родителю уходил сырой текст с `to=self`/`assistant to=bash`.
  Субагент переведён на общий `StreamParser` (стопы, парсер, чистый текст,
  каноническая реплика в локальной истории).
- **Bing без результатов** отдаёт брендовые заглушки над плашкой «There are
  no results» (`li.b_no`); парсер принимал их за выдачу, и Muse искала по
  кругу 20 ходов. Теперь такая страница — `Empty`, модели уходит честная
  ошибка. С казахстанского выходного IP DDG, Bing, Mojeek и Yahoo закрыты
  капчей или отдают мусор — поиску нужен свой SearXNG или VPN.
- **Реплика ассистента для шаблона: размышления и структурные вызовы.**
  Реплика, собранная текстом (`<think>` руками, `<tool_call>`-JSON руками),
  ломала префикс-KV на flash-next полностью («0 из N» каждый ход, +8 с
  префилла на ход): промпт хода заканчивается `…assistant⏎<think>⏎`, а
  шаблон Qwen3.x рендерит реплику из полей `reasoning_content` и
  `tool_calls`, и без них выдаёт `<think>⏎⏎</think>⏎⏎` — токен `⏎⏎` не равен
  `⏎`. У гибрида это скрывало выравнивание точки возврата на 64.

  Правка сквозная. В `synaptix-tokenizer` у `Message` появилось поле
  `reasoning_content` и конструктор `assistant_with_reasoning`; перед
  рендером `arguments` вызова разворачивается из строки в объект
  (`objectify_tool_call_arguments`) — шаблон Qwen3.8 перебирает их как
  `tool_call.arguments|items` и на строке молча терял параметры. В фасаде
  `synaptix::facade::llm::Message` получил `reasoning` и `tool_calls`, плюс
  конструктор `assistant_turn`. В synthos реплика хода собирается
  `assistant_turn_message` (текст + размышления + разобранные вызовы), а
  `HistoryItem` несёт `reasoning`/`calls`, чтобы пересборка из ленты давала
  тот же промпт. Размышления обычного текстового ответа тоже переносятся:
  без них расходился первый ход следующего сообщения пользователя.

  Проверено на flash-next (точка возврата на конце промпта, расхождение
  видно сразу): было «0 из 914 / 0 из 1012 / 0 из 1100 / 0 из 1174», стало
  «0 из 914 / 914 из 1029 / 1029 из 1112 / 1112 из 1191» — переиспользуется
  всё, включая переход между сообщениями. Инвариант закреплён тестами
  `assistant_turn_with_reasoning_keeps_previous_prompt_as_prefix` и
  `assistant_turn_without_thinking_keeps_prefix_too` в
  `crates/synaptix-tokenizer/tests/qwen38_template.rs`: промпт хода обязан
  оставаться префиксом промпта следующего хода.

  Заодно в журнал добавлена диагностика: при reuse 0 пишется позиция
  расхождения и оба фрагмента вокруг неё — без неё причина не видна.
- Анти-loop температура поднята до 0.85: дефолт сэмплинга теперь 0.6, и
  прежний порог 0.6 ничего не менял.
- Bing с этого IP отдаёт и вовсе чужие выдачи без маркера («10 лучших
  отелей Пунта-Каны» на postmarketOS) — добавлена проверка релевантности:
  выдача принимается, только если в ней есть хотя бы половина слов запроса
  (не меньше двух).
- Парсер `function=`-стиля: значение без `</parameter>` (flash-next обрывает
  блок сразу после JSON) берётся до `</function>`/конца, как в `invoke`-стиле.
- Метки времени в ленте — локальные (проверено: 15:45 при 10:45 UTC).

Наблюдения без правок: qwen3.8/3.6 при temp 0.6 изредка выдают битый вызов
(один-два на сообщение) и исправляются следующим ходом — guard аргументов
и валидатор это держат. Muse-Glimmer как агент слабее: повторяет вызов после
успешного результата и игнорирует подсказку guard'а; при малом лимите
контекста цикл «компакт → повторный обход» съедает бюджет ходов.

## Фоновая генерация и OOM (04.09.2026)

Две жалобы после установки пакета 173.

**«При переключении чатов или вкладок останавливается генерация.»** Так и
было задумано: `registry::select` бампал abort, потому что воркер писал в
общую ленту, и в чужом чате его сообщения оказались бы не к месту. Теперь ход
принадлежит своему чату (`SynChatCtx::generating_chat`) и доигрывает в фоне:
`session::ledger_update` правит открытый чат в UI, а фоновый — прямо в его
файле, откуда `select` его и прочитает; живой стрим, статистика и плашки
ошибок идут через `if_active`; `commit_turn_text` переливает текст хода
(фоновому чату — из копии воркера, иначе терялся финальный ответ). Кэш
префикс-KV при уходе больше не роняется, пока идёт генерация. Вторая
генерация параллельно первой не запускается — одна карта на всех.

Проверено раннером (`SYN_SMOKE_SWITCH_AFTER_S=5`): уход из чата на пятой
секунде, ход доиграл 114 с и семь ходов, в файле чата 15 сообщений вместе с
финальным ответом.

**OOM на muse-glimmer-30b** (`alloc_zeros(112220160) after trim+retries`,
промпт 8430, веса 21 ГБ из 24). Аллокация — KV ровно на длину промпта
(13312 Б/ток × 8430). Дефект был в ретрае: он сбрасывал кэш префикс-KV на
416 МБ и тут же создавал его заново того же размера, падая на той же
аллокации — три попытки подряд делали одно и то же, потом ход обрывался.
Теперь после первой нехватки памяти ход доигрывается без префикс-KV, а
следующие попытки режут бюджет ответа.

Заодно ёмкость сессии берётся с запасом вдвое от нужного ходу (в пределах
честного бюджета): пересоздание стирает префикс, и там, где бюджета хватает
на пару шагов, каждый рост промпта стоил полного префилла. На том же
сценарии пользователя (заметки + bash, 15 вызовов, 217 с) Muse отработала
без единого OOM, кэш пересоздался один раз вместо трёх, и дальше префикс
переиспользуется на каждом ходу: 8292/8516, 9413/9716, 11324/11800 …

Что осталось нерешённым: полный контекст модели (131k у Muse) в 24 ГБ вместе
с 21 ГБ весов не помещается — под KV остаётся около двух гигабайт, это ~45k
токенов по расчёту и меньше на практике. Честный ответ здесь — частичный
оффлоад весов: в synaptix есть послойный host-stream
(`DecoderModel::build_with_block_device`, `host_stream_blocks`), но он
работает по принципу «все блоки на хосте» и подключён только к Gemma3; для
21 ГБ это секунды на токен. Нужен режим «N блоков на карте, остальные
стримятся», с автоматическим выбором N по свободной памяти.

## Файл «не читается до конца» и петля внутри генерации (07.09.2026)

Чат «MyLife», qwen3.8-27b, temperature 0, thinking off: «прочитай
`doc_big.md` (749 строк, 55 КБ) полностью и сделай аналитику». Модель читала
файл `sed -n` кусками по 250 строк, после третьего куска снова запрашивала
100–260 и так по кругу; четыре попытки, каждая кончалась «Стоп» пользователя
(в журнале — ход с 0 токенов без WARN: abort до первого токена).

**Корень — статический клип результата инструмента.** В промпт уходила копия
выхлопа, обрезанная до 8000 символов (голова 5333 + пометка + хвост 2667), а
кусок в 250 строк выписки — 16 КБ. Модель видела дыру посередине и подпись
«уточните команду, если нужен весь вывод» — и честно дозапрашивала середину,
которую резало снова. Второй заход дошёл до 11 вызовов `sed` и 57k токенов
промпта без единой целой страницы.

**Правка:** клип по символам снят везде. Выхлоп инструмента укладывается в
остаток окна хода по токенам (`tools::budget::fit` через
`session::fit_for_prompt`; для `bash`, `web`, `kb_search`, `system`,
`pipelines`, `subagent`; `autoskill` и `notes` — как раньше, целиком/своим
бюджетом), в ленту уходит та же копия, `build_history` её не трогает. Сырой
предохранитель `bash`/`web` — 256 КБ. Документ-вложение меряется тем же
`fit_with` по половине окна чата (`attach::prompt::DocBudget`).

**Живой прогон после правки (`agent_smoke`, тот же промпт и параметры):**
три куска `sed` ушли в промпт целиком (+11k токенов каждый вместо +5,5k),
модель перешла к аналитике — и на python-скрипте с картой категорий
зациклилась внутри одной генерации: `'LILIT','LILIT',…` на 18k токенов
(8 минут), оборванная строка → `SyntaxError`, следующий ход — то же самое.
Guard'ы вызовов такое не видят: петля живёт внутри одного вызова.

**Второй guard — периодичность текста хода** (`periodic_tail` по символам
декодированного стрима, `LOOP_WINDOW_CHARS` = 3072, период ≤ 384 символов,
проверка раз в 64 токена): стрим обрывается, ход отбрасывается целиком
(истории и ленте он не достаётся, префикс-KV цел), следующий ход идёт с
`LOOP_NOTE` от лица пользователя и анти-loop температурой 0.85; второй
зацикленный ход подряд — `stop_reason` «модель зацикливается в генерации».
Первый вариант guard'а по id токенов (окно 1024, период ≤ 128) на той же
петле сработал лишь на 18672-м токене — на MTP-декоде гибрида одинаковый
текст выходит разной нарезкой токенов, поэтому мера — символы.

## Два лишних хода на `notes kanban add_card` (08.09.2026)

Чат «MyLife», qwen3.8-27b, temperature 1.0, thinking off: «добавь задачу для
synthos — не могу перемещать страницы по порядку в Заметках». Модель нашла
доску (`list` → `read`) и собрала вызов
`{"action":"kanban","board":…,"column":"К выполнению","card":"<текст>","priority":"medium","tags":[…]}`
— без `op` и с текстом карточки в `card`. Ответ инструмента: «Invalid
arguments JSON: missing "op" (create | read | … | delete)». Модель добавила
`op=add_card`, но `card` оставила — «Invalid arguments JSON: missing "title"».
Третий заход прошёл. Пользователь прочитал это как «неполный JSON».

**Корни.** (1) Схема `notes` — одна плоская сумка из ~90 полей, а сигнатуры
операций доски нигде не собраны: `op` перечислял имена, `card` описывался
как «card id or exact title» — модель и положила туда заголовок новой
карточки. (2) Все ошибки `notes::dispatch` уходили как
`ToolError::BadArgs` с префиксом «Invalid arguments JSON», хотя JSON был
целым: слово «JSON» уводит и модель, и пользователя искать битый синтаксис.

**Правка.** `ToolError::Args` («Invalid arguments: …», тот же
`invalid_args=true`) для ошибок после разбора JSON; у `kanban` ошибка без
`op` и с неизвестным `op` отдаёт шпаргалку `KANBAN_OPS_HELP` — каждая
операция со своими полями; `add_card` принимает `card` как заголовок, если
`title` не задан (другого смысла у поля в этой операции нет); в схеме
описание `op` для kanban — те же сигнатуры, `card` помечен как «существующая
карточка, не для add_card», `title` — «текст новой карточки (обязателен)»;
в системном промпте — `add_card {column, title, md, priority, tags, due,
repeat}` и `card=<id|title существующей>`. Тесты:
`kanban_add_card_tolerates_card_as_title_and_explains_ops`,
`notes_argument_error_has_no_json_word`, `notes_rules_only_with_notes_tool`.
Отдельно: у чата стояла temperature 1.0 (дефолт 0.6) — при ней модель
чаще угадывает имена полей вместо того, чтобы читать схему.

## Пинг-понг трёх блоков мимо guard'а подбора чисел (14.09.2026)

Чат MyLife, «Долги и кредиты»: 32 вызова `notes blocks set_attrs` без
текстового ответа — модель гоняла блоки #14, #24, #25 по y. Guard
`numeric_masked_key` (ключ вызова с числами под маской + счётчик одинаковых
по сути результатов) маскировал и номер блока: у трёх блоков был один ключ,
ответы у них разные, и счётчик обнулялся на каждой смене блока. Сработали
только точные повторы (3 из 32). Теперь числа в аргументах-адресах
(`ADDRESS_ARGS`: `block`, `index`, `after`, `into`, `page`, `card` …) остаются
в ключе — у каждого блока свой счётчик, четвёртый по сути одинаковый перенос
того же блока не исполняется. Корень самой петли — фантомная `h=2100` у
toggle и заголовки без своих пунктов — разобран в
`notes_agent_tool_2026.md`, «Пинг-понг координат вокруг toggle». Тест —
`numeric_masked_key_sees_a_ping_pong_of_several_blocks`.
