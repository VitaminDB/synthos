Все — плотный BF16 (VAE — F32, как в исходнике), `arch flux.2`, `purpose image`.
klein base-4B — недистиллированный klein (50 шагов, настоящий CFG); его
текстовый энкодер, токенайзер и VAE байт в байт те же, что у klein-4B (LFS-хэши
совпадают), поэтому в каталоге они — жёсткие ссылки на `FLUX.2-klein-4B/`, а
скачан только трансформер (SHA-256 сверен с LFS).
Квант NVFP4/MXFP8 делается при загрузке DiT.

**Проверка исходников.** FLUX.2-dev: все 39 файлов совпали по SHA-256 с хэшами,
которые загрузчик synthos записал из LFS-метаданных HF при скачивании
(`~/.config/synthos/hf_downloads.json`), размеры — с текущим деревом репозитория,
заголовки safetensors целые. Два оставшихся `.part.meta` (от докачки
`ae.safetensors` и 7-го шарда трансформера) — устаревшие: хэши этих файлов верные;
убраны из каталога. klein-4B — SHA-256 против `lfs.oid` официального репозитория.
klein-9B — официальный репозиторий gated, а HF-токен на машине
(`~/.config/huggingface/token`) недействителен (401), поэтому скачан с зеркала
unsloth: SHA-256 всех весов совпали с `lfs.oid` зеркала, те же `oid` у второго,
независимого зеркала `ModelsLab/FLUX.2-klein-9B`, размеры — с официальным деревом.

**Упаковка:**

```sh
cd ~/Storage/syn_models
~/Projects/2027/synaptix/target/release/syn-pack FLUX.2-dev -o flux.2-dev.syn \
  --id flux.2-dev --version 1.0.0 --arch flux.2 --purpose image
# так же FLUX.2-klein-4B → flux.2-klein-4b.syn, FLUX.2-klein-9B → flux.2-klein-9b.syn

  --test bundle_source -- --ignored --nocapture   # тензоры байт в байт
```

Упаковщик сам пропускает корневые `flux2-dev.safetensors` / `ae.safetensors`
(формат BFL — дубли весов из подкаталогов). Бандлы байт в байт совпадают с
каталогами: 818 / 883 / 1167 тензоров.

## synaptix: `synaptix-image-flux2`

- **Энкодер текста** (`text_encoder.rs`): свой лёгкий декодер Mistral / Qwen3 до
  последнего нужного слоя (30 из 40 у Mistral, 27 из 36 у Qwen3); выход — склейка
  `hidden_states` слоёв 10/20/30 (dev) или 9/18/27 (klein). Слои, не влезшие в
  VRAM, читаются из mmap-источника по одному прямо в forward, копии на хосте нет.
  Паддинг до 512: токенайзер Mistral паддит **слева**, Qwen3 — справа (так в HF;
  строки-паддинги слева получают нули из SDPA).
- **DiT** (`transformer.rs`): размеры из конфига, общая модуляция, SwiGLU, RoPE по
  четырём осям. Модуляция и `norm_out` всегда плотные: NVFP4 на них даёт косинус
  шага 0,81 к эталону, MXFP8 — 0,997.
- **VAE** — общий `AutoencoderKl` (32 канала) + пакет 2×2 и нормировка статистикой
  BatchNorm.
- **Референсы**: токены картинок идут в ту же последовательность с `t = 10, 20, …`.
- Стадии `Flux2Model`: `encode_prompt`, `encode_references`, `load_transformer`,
  `sample` (отмена, img2img-заготовка `init`), `decode`.

**Сверка с diffusers 0.40** (`tests/reference.rs`, эталоны —
`scripts/reference/gen_flux2_*.py`, CPU F32): klein-4B — токены бит в бит,
эмбеддинги промпта косинус 0,9999, шаг DiT BF16 0,99988 / MXFP8 0,996 / NVFP4
0,973, VAE совпадает, полная генерация 512² с тем же шумом: BF16 PSNR 40 дБ.
dev — эмбеддинги Mistral косинус 0,99994 против послойного эталона (эталонные
токены пришлось брать из «сырого» `tokenizers`: transformers 5.12 грузит этот
токенайзер как `LlamaTokenizer` и теряет пробелы). DiT dev целиком на CPU не
поднять, поэтому сверен урезанный (`gen_flux2_dev_mini.py`, тест
`dev_mini_dit_matches`): один double- и один single-блок на настоящих весах,
все эмбеддеры, guidance-эмбеддинг (его у klein нет), модуляция, финал. В F32 —
косинус 1,000000, вклад guidance (g=4 − g=1) с относительной ошибкой 0,0001; в
BF16 — 0,999994.

## Память: всё работает при 7 ГБ VRAM

`tests/low_vram.rs` (оба крейта): балласт в VRAM оставляет модели 7 ГБ,
фоновый поток ловит минимум свободной памяти. 1024²:

| модель / веса DiT | что стримится | время | минимум свободной из 7 ГБ |
|---|---|---|---|
| klein-4B NVFP4 / MXFP8 / BF16 | BF16: 16 из 25 блоков с хоста | 4 шага 2–3 с | ~1,2 ГБ |
| klein-9B NVFP4 / BF16 | BF16: 30 из 32 с хоста; энкодер 15/27 слоёв из mmap | 4 шага ~5 с | ≥ 1,0 ГБ |
| dev NVFP4 | 55 из 56 блоков с хоста, Mistral 28/30 слоёв из mmap | 28 шагов 115 с, энкодер 6,5 с | 1,27 ГБ |
| FLUX.1-dev NVFP4 / MXFP8 / BF16 | T5 13/24 блоков из mmap, DiT частично с хоста | 20 шагов 13 / 16 / 28 с | ≥ 0,67 ГБ |

Не влезшие блоки DiT держатся пиннованной копией на хосте (квант один раз при
загрузке); если и RAM не хватает (`MemAvailable` < объём + 12 ГБ) — читаются из
mmap-источника на каждом шаге. Следующий блок едет на loader-стриме во время
счёта текущего.

**FLUX.1 доработан под то же:** T5-XXL стримит блоки из источника
(`T5Encoder::load_budgeted`), квантованный DiT больше не кладётся на карту целиком
(`FluxTransformer::load_budgeted`), префетч блоков в forward (`stream_each`),
перед VAE и энкодерами пулы возвращаются драйверу (раньше на VAE 1024² в 7 ГБ
оставалось 0,03 ГБ).

## Остальные тяжёлые модели при 7 ГБ (19.09, вечер)

Полная сводка по всем моделям (чат-LLM, TTS, музыка, видео) — в
`small_vram_7gb_2026.md`. Ниже — первый заход; строка про чат-LLM устарела:
теперь проходят и они.

Проверено смоуками synthos с балластом отдельным процессом (занимает всё,
кроме 7 ГБ; `ballast.cu` — `cudaMalloc` и сон):

| модель | что пришлось сделать | результат |
|---|---|---|
| MiniMax-H3 (NVFP4, 640×384, 2 с) | VAE: блоки ViT-декодера стримятся из бандла (18/36 на карте); повтор VAE после отпускания удержанного DiT; `trim_pool` — все пулы | энкодер 17 с, сэмплер 46 с, VAE 14 с, mp4 со звуком |
| LTX-2.3 distilled (512×320, 2 с) | Gemma в MXFP8 — host-stream блоков; признаки порциями, агрегатор без транспонированной копии; тримы всех пулов в Text Encoder/NAG; видео-коннектор отпускается до аудио | энкодер 6 с, NAG 6 с, stage1 22 с, mp4 49 кадров |
| ACE-Step xl (плотный, 8 с) | слои DiT на хост и стриминг (9/32 на карте) | 8 шагов 3,6 с, звук бит в бит с прогоном без ограничения |
| чат-LLM | нода LLM подгоняет резидентность блоков, как чат | qwen3.8-27b: даже при 0/64 блоков на карте не-блочные части (эмбеддинги, lm_head, башня зрения) занимают ~5,5 ГБ — генерация в 7 ГБ не помещается; gemma-4-26b (MoE) грузит всех экспертов на карту — оффлоада экспертов у этой архитектуры нет (есть только у Qwen4Exp) |

**Найдено по пути.** (1) Ядра, запущенные из потока префетча (приведение типа,
квант), не ждут копию на loader-стриме: при стриминге весов, которые надо
привести к другому типу, выходил мусор (кадр H3 из шума). Правило: поток
префетча только копирует (в типе файла) и синкает loader-стрим, всё остальное —
в основном потоке. У FLUX.2 так сделан путь «из источника». Стриминг T5 и
LLM-энкодеров безопасен — веса BF16, приведения нет. (2) Захват денойза
ACE-Step CUDA-графом падал `CUDA_ERROR_ILLEGAL_INSTRUCTION` и без моих правок
(плотный DiT с CFG — это умолчание нод): граф теперь только по
`SYN_ACESTEP_GRAPH=1`, обычный путь даёт тот же звук. Причину не искал.

## synthos: ноды «Нейро → FLUX.2»

- **FLUX.2 Checkpoint** — бандл/каталог, устройство, веса DiT
  `nvfp4 | mxfp8 | dense (bf16)` (по умолчанию mxfp8), память
  `auto | resident | block_offload`, «Держать в памяти».
- **FLUX.2 Text Encoder** — промпт → кондиционирование; повтор с тем же промптом
  берёт готовое (у dev энкодер — Mistral-24B).
- **FLUX.2 Reference** — картинка → токены для правки (площадь до 1 Мп, стороны
  кратны 16); цепочкой через вход/выход `references`, до 10 штук.
- **FLUX.2 VAE Encode** — картинка → латент для img2img (размер со входа size
  или сама картинка до 2 Мп).
- **FLUX.2 Sampler** — шаги (0 — по модели: dev и klein base 50, klein 4),
  guidance (dev — эмбеддинг, klein base — CFG, дистиллированный klein
  игнорирует), seed, denoise (img2img: латент с картинкой на входе latent);
  размер — с FLUX Empty Latent / VAE Encode или с первого референса.
  Denoise — время начала до сдвига расписания (`Flux2Scheduler::with_strength`),
  все шаги в работе: у klein 0.6 почти оставляет картинку, 0.7 меняет стиль
  при той же раскладке, 0.8 рисует заново. Срез шагов «как в diffusers» не
  годится: сдвиг FLUX.2 прижимает sigmas к единице, и 0.6 начиналось с σ ≈ 0.96.
- **FLUX.2 VAE Decode** — картинка с превью.

Empty Latent — общий с FLUX.1. Шаблоны (раздел «Картинки»):
`builtin-flux2-text-to-image`, `builtin-flux2-edit`, `builtin-flux2-image-to-image`
(denoise 0.7), `builtin-flux2-multi-reference`.
Агент: подсказки `*_idx` FLUX.2, формат промпта `agent/tools/flux2_prompt.md` при
открытии шаблона, каталог инструментов упоминает правку по референсам; прогон из
чата прикладывает PNG из FLUX.2 VAE Decode, если Image Save нет.

Смоук без GUI (настоящие `on_run` нод):

```sh
cargo run --release --bin flux2_smoke -- ~/Storage/syn_models/flux.2-klein-4b.syn out.png 1024 1024
# FLUX2_EDIT=src.png [FLUX2_EDIT2=…] — правка; FLUX2_INIT=src.png FLUX2_DENOISE=0.7 — img2img;
# FLUX2_VRAM_GB=7 — «малая карта»;
# FLUX2_QUANT=nvfp4|mxfp8|dense, FLUX2_REPEAT=2 FLUX2_RESIDENT=1
```
