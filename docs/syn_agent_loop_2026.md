# Agent-loop Syn-чата: почему он зацикливался — раунд 2026-08-19

Разбор по сохранённому чату `~/.config/synthos/syn_chats/18cd2c92449c4fd5.json`
(модель — гибрид Qwen3.8-27B, `agent_max_turns = 32`, per-chat
`temperature = 0.0`, `enable_thinking = false`).

## Симптом

268 сообщений на **один** запрос пользователя:

| метрика | значение |
| --- | --- |
| tool-вызовов | 133 |
| уникальных вызовов | 28 |
| один и тот же `bash`-вызов | **106 раз** |
| длина непрерывной серии одинаковых вызовов | 105 (с сообщения 57 и до конца) |
| текстовых ответов модели | 0 |
| рост тела диалога | 25k → 74k символов внутри одного хода |

Команда, на которой агент застрял, — `grep -n "fn request" -A 30
src/lyrics/mod.rs | head -40`: первый раз она прозвучала на 47-м сообщении,
повторилась на 57-м и дальше воспроизводилась дословно до упора в лимит ходов.
«Продолжить» нажималось четырежды (32 × 4 + 5 = 133) — и каждый раз цикл
продолжался с того же места.

## Разбор причин

1. **У Syn-чата не было системного промпта вообще.**
   `AppConfig::syn_chat_system_prompt` по умолчанию пуст, а `build_history`
   пустую строку просто не добавляет в историю. Модель с `bash` в руках
   работала без роли, без окружения (дата, ОС, рабочий каталог) и — главное —
   без критерия остановки.
2. **В agent-loop не было защиты от повторов.** `run_agent_loop` исполнял всё,
   что пришло, не сравнивая вызов с предыдущими. При
   `tool_approval_default = always_allow` 106 одинаковых `bash` отработали
   молча.
3. **Сэмплинг не сопротивлялся вырождению.** `temperature = 0.0` →
   `GreedySampler`: контекст, заканчивающийся N одинаковыми парами
   `tool_call`/`tool_result`, — аттрактор, из которого greedy не выходит по
   определению. `repeat_penalty` при этом применялся **ко всему контексту**
   (штраф по половине словаря на промпте в 30k токенов — шум), а
   `repeat_last_n`, `presence_penalty` и `frequency_penalty` вообще не
   доходили до движка: поля есть в `GenerationOptions` и в UI, но в
   `GenerationConfig` (`llm/common`) их не было. Плюс `seed = -1`
   («энтропия из ОС») превращался в константный `0`, то есть один и тот же
   PRNG на каждом ходу.
4. **Автокомпакт внутри хода не работал в принципе.** `maybe_autocompact`
   звался только после завершения agent-loop, а `find_compact_range` считает
   «свежим» всё после последнего user-сообщения — а у агента весь рост
   контекста именно там.
5. **Вывод инструмента уходил в промпт целиком** (потолок `MAX_OUTPUT_BYTES`
   — 64 КБ). Первый же `ls + cat` дал 14,6 КБ.
6. Мелочи: имя модели в файле чата не сохранялось (`model_name: None`
   захардкожено); прерывание оставляло в ленте пустой assistant-пузырь,
   который потом уезжал в промпт пустой репликой; предупреждение про
   непомещающийся промпт обещало, что «движок обрежет историю», хотя движок
   либо падает с `KV overflow`, либо (со скользящим окном) молча выбрасывает
   голову контекста — системный промпт и задачу.

## Что сделано

### Системный промпт агента — `syn_chat::system_prompt`

Базовые правила (роль, дата, ОС, рабочий каталог, список активных
инструментов, правила «не повторяй вызов», «хватает данных — отвечай», «застрял
— скажи об этом», «перед необратимым действием предупреди») плюс бюджет ходов.
Пользовательский промпт их не заменяет, а дописывается снизу. С 07.09.2026 это
активный пресет библиотеки промптов (`syn_chat::prompt_presets`, файл
`~/.config/synthos/syn_system_prompts.json`; правая панель → «Система»:
дропдаун пресетов, создать/переименовать/удалить, редактор в отдельном
плавающем окне для длинных промптов).

Времени в промпте намеренно нет: он лежит в голове контекста, и любое
ежеминутно меняющееся поле обнуляло бы переиспользование префикс-KV между
сообщениями. Остаток бюджета ходов по той же причине дописывается не в
`system`, а к результату инструмента (`system_prompt::budget_note`), начиная за
3 хода до конца.

### Guard повторов — `syn_chat::session`

Ключ вызова — имя инструмента + канонизированный JSON аргументов (модель
переформатирует JSON от хода к ходу, для guard'а это один и тот же вызов).

* 2-й одинаковый вызов **подряд** не исполняется: модель получает вместо
  результата заметку «между двумя одинаковыми вызовами подряд ничего не
  произошло, смени подход».
* 3-й подряд останавливает ход: в UI — ошибка «агент ходит по кругу», кнопка
  «Продолжить» остаётся доступной.
* Не-подряд повторы (правка файла → та же команда сборки → правка) исполняются
  как обычно; начиная с 3-го к результату дописывается подсказка.
* Состояние guard'а восстанавливается из ленты (`repeat_state_from`), поэтому
  «Прервать»/«Продолжить» больше не перезапускает петлю с чистого листа.

Первый же сработавший guard включает анти-loop сэмплинг на оставшиеся ходы:
`temperature ≥ 0.6` (greedy из петли не выходит никогда) и
`frequency_penalty ≥ 0.25` по окну в 256 токенов. Пользовательские настройки
только повышаются, не понижаются.

### Сэмплинг — `synaptix`

* `GenerationConfig` (`llm/common`) получил `repeat_last_n`,
  `presence_penalty`, `frequency_penalty`; фасад `LlmGeneration` прокидывает их
  во все три пути генерации (обычный, префикс-KV, медиа). Ручки в UI Syn-чата
  перестали быть мёртвыми.
* `RepetitionPenaltyProcessor` научился окну (`last_n`, `0` = весь контекст),
  добавлен `PresenceFrequencyProcessor` (OpenAI-семантика: аддитивный сдвиг
  `presence + frequency × count`) — он и гасит зацикливание, потому что растёт
  с числом повторов.
* `TokenSampler` больше не копирует весь контекст в `ProcessorContext` на
  каждом шаге декода: при окне копируется только хвост, при выключенных
  штрафах — ничего. На промпте агента в 30k токенов это было 120 КБ memcpy и
  30k итераций штрафа **на каждый токен**.
* `seed = -1` теперь честно берёт энтропию (наносекунды + счётчик,
  splitmix64-финализатор), так что два хода с почти одинаковым промптом не
  воспроизводят один и тот же ответ.

### Контекст внутри хода — `syn_chat::compact`

* `find_compact_range_in_turn` сжимает tool-цепочку **текущего** хода, оставляя
  дословно сам запрос пользователя и последние 3 сообщения ленты; общая часть
  с межходовым поиском (атомарность tool-пар) вынесена в `refine_range`.
* `maybe_compact_in_turn` зовётся из `run_agent_loop` между ходами, когда
  промпт перевалил за `autocompact_threshold_percent` от честного
  VRAM-бюджета хода (`RingPlan.by_mem`, ограниченный окном модели). Перед
  summary-запросом agent-loop сам освобождает свой кэш префикс-KV, после
  сжатия — пересобирает историю из ленты (`rebuild_history`). Медиа-путь не
  трогаем: там история завязана на посчитанные эмбеддинги.
* Результат инструмента уходит в промпт обрезанным до 8000 символов
  (голова + хвост, середина заменяется пометкой — в хвосте живут exit-код и
  stderr). В UI пузырь остаётся полным.
* Исключение — `autoskill`: скил не выхлоп команды, а инструкция, которую
  модель обязана выполнить целиком, поэтому копия для промпта не режется
  (`history_clip_limit`), а потолок executor'а для него вчетверо выше
  общего (`MAX_SKILL_OUTPUT_BYTES` = 256 КБ против 64 КБ). Плата —
  контекст: скил на 90 КБ занимает его надолго.

### Мелочи

* `snapshot_current` пишет имя загруженного бандла в файл чата.
* Пустой assistant-пузырь снимается в финализации хода; `build_history` теперь
  выкидывает пустые assistant-реплики где угодно, а не только в хвосте.
* Предупреждение про непомещающийся промпт говорит правду про поведение
  движка.

## Что осталось

`build_history` собирает историю tool-вызовов в ChatML-формате
(`<tool_call>…</tool_call>`) независимо от протокола модели. Для канальных
моделей (Muse Glimmer, ATEM) внутри хода используется
`channel_parser::rebuild_turn_text`, но после перезагрузки чата или
«Продолжить» история пересобирается в чужом формате. Проблема не новая и этим
раундом не затронута.
