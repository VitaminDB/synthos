# Режим «Заметки» (2026-09)

Notion-редактор поверх **проекта в одном файле `.syn`**. На нав-рейле —
одна плитка на проект (подпись — имя файла); слева — дерево страниц
«Содержимое», в центре — редактор активной страницы, справа — вкладки
«Свойства | Связи». Вставка блоков — правым кликом в документе или через
slash-меню «/».

Первая волна (vault-папка с `.md`, плитка на каждую страницу, вкладка
«Вставка», базы/канвасы как отдельные файлы-страницы) переделана
2026-09-02; старая папка `~/Documents/SynthOS Notes` мигрирует в проект
автоматически при первом запуске (папка `X/` рядом с `X.md` → дети
страницы X). «База данных» (таблица/канбан/ганнт одним виджетом) и
«канвас» убраны тем же днём: вместо них — самостоятельные примитивы
канбан-доска и диаграмма Ганта (см. ниже); `*.base.json`/`*.canvas.json`
при миграции пропускаются, а старые врезки `![[base:…]]`/`![[canvas:…]]`
в страницах остаются карточками-заглушками.

## Хранение: проект = бандл synaptix-bundle

`pages/notes/project.rs`. Файл — `AppConfig.notes_project_path`, дефолт
`~/Documents/SynthOS Notes.syn` (`BundleMeta.purpose = "notes"`).
File-чанки внутри:

| Путь в бандле                    | Содержимое                                   |
|----------------------------------|----------------------------------------------|
| `notes/tree.json`                | дерево страниц: `{id, title, icon, children}` |
| `notes/pages/<id>.md`            | страница, расширенный markdown               |
| `notes/objects/<id>.kanban.json` | канбан-доска (блок `![[kanban:<id>]]`)       |
| `notes/objects/<id>.gantt.json`  | диаграмма Ганта (блок `![[gantt:<id>]]`)     |
| `notes/objects/<id>.mindmap.json`| интеллект-карта (блок `![[mindmap:<id>]]`)   |
| `notes/objects/<id>.calendar.json`| виджет календаря (блок `![[calendar:<id>]]`) |
| `notes/objects/<id>.chart.json`  | график (блок `![[chart:<id>]]`)              |
| `notes/calendar.json`            | единое хранилище событий календаря           |
| `notes/assets/<sha256>.<ext>`    | вложения (`asset:<sha256>.<ext>` в markdown) |

Ключ страницы — стабильный id (12 hex): переименование и перенос по дереву
не трогают ни файлы, ни ссылки. Страница универсальна: доска, диаграмма,
врезка другой страницы, медиа — блоки внутри неё; отдельных типов узлов в
дереве нет.

Запись — `BundleEditor` (append-only журнал + fsync, ~10 мс на commit):
`autosave.rs` собирает грязные ресурсы (страницы/объекты по ревизии ручек,
дерево по `tree_rev`, вложения и удаления) и после ~700 мс тишины
применяет их **одним commit'ом**. Файл растёт с каждым коммитом —
`compact_if_needed` при открытии уплотняет, когда мёртвых байт больше
живых. Чтение — mmap-кэш (`project::bundle`), сбрасываемый после commit'а.
Вложения для плееров распаковываются в
`~/.cache/synthos/notes-assets/<проект>/` при первом обращении
(`media.rs`); дроп файла → sha256 → чанк + `handle.patch_media`.

## Оболочка

- `rail.rs`: `RailEntry::Notes(opened_at)` — одна плитка, ключ `notes`;
  «+» → Заметка показывает плитку (и создаёт первую страницу в пустом
  проекте); закрытие плитки дописывает хвост автосейва.
- `contents.rs` — «Содержимое»: строки — DFS по дереву с учётом
  `expanded`; шеврон сворачивает, клик активирует, клик по иконке
  открывает панель иконок. DnD строки: верхняя/нижняя кромка — перед/после,
  середина — внутрь (`ROW_H` фиксирована в MSS). Контекстное меню:
  новая внутри, переименовать (inline `TextField`), дублировать (копия
  поддерева с клонами объектов), удалить (с поддеревом и объектами).
- `icon_picker.rs` — `PopupPanel` с вкладками «Эмодзи» (категории) и
  «Иконки» (Material). Эмодзи рисуется текстом (feature `color-emoji`
  syngui), Material-глиф (PUA) — `Icon`; `render_icon` выбирает сам.
- `doc_menu.rs` — контекстное меню документа: «Вставить ▸» и «Превратить
  в ▸» разбиты на категории-подменю («Текст», «Списки», «Блоки»,
  «Объекты», «Примитивы», «Медиа» — плоский список не влезал на экран),
  дублировать/сдвинуть/удалить блок (`block_action_items`, те же пункты у
  строки панели «Блоки»); плюс локализованный slash-каталог с пунктами
  «Канбан-доска»/«Диаграмма Ганта» (`on_slash_custom`). Правый клик по
  фигуре или врезке-объекту делает *их* текущим блоком (каретка в соседний
  текст не прыгает — «Удалить блок» удаляет именно объект).
- `blocks.rs` — «Блоки»: дерево блоков активной страницы (вторая вкладка
  левой панели; в шапке — название только активной вкладки, переключает
  иконка соседней: две подписи в узкую панель не влезают). Пустой блок в документе не виден вовсе — в дереве он есть
  строкой со своим типом, по клику становится текущим (`DocOp::Select`;
  редактор при этом просит фокус приложения обратно —
  `focus_request_pending`, иначе после клика по панели он был бы
  «фокусирован» сам по себе). Строка текущего блока подсвечена; правый
  клик — дублировать/сдвинуть/удалить (выбор + действие очередью, удаление
  адресное `DocOp::DeleteBlock`). Источник — `DocumentEditorHandle::outline`,
  выбор общий с редактором через сигнал `handle.selected()`.
- `right_panel.rs` — «Свойства» (страница: название, иконка, путь,
  **раскладка**, и ниже — **свойства текущего блока**), «Связи»
  (мини-граф, backlinks, исходящие).
- Граф связей — кнопка в шапке «Содержимого» (`show_graph`), не узел дерева.

Конфиг: `notes_project_path`, `notes_active` (id), `notes_expanded`,
`notes_tile_opened_at`; `notes_vault_path` остаётся только как источник
миграции.

## Раскладка страницы

`PageNode.layout` в `tree.json` (дефолт в файл не пишется): `free`
(**по умолчанию включена**), `grid` (`none|dots|lines|cross`), `grid_step`,
`snap` (**включена**, шаг **5 px**), `snap_step`, `bg` (фон страницы
`#rrggbb`/`#rrggbbaa`, пусто — тема; в редактор уходит как
`DocLayout.background` и заливается под сеткой на весь холст в обоих
режимах). Управление — «Свойства ▸ Раскладка» (фон — пресеты подложек +
`ColorPicker`); агенту — `update {layout grid grid_step snap snap_step bg}`.

Свободная раскладка **гибридная**: блок с координатами стоит на холсте,
блок без них остаётся в колонке потока. Поэтому страница, которую ещё не
двигали мышью, выглядит ровно как обычный документ — и включённый по
умолчанию режим ничего не ломает в старых проектах. Координаты появляются
только у того блока, который перенесли, растянули или вставили правым
кликом в точку; при первом переносе блок закрепляется **там, где он сейчас
нарисован** (`pin_block`), поэтому скачка нет.

- ручка ⋮⋮ переносит блок (с привязкой), правая кромка тянет ширину;
- правый клик по пустому месту ставит новый блок в точку клика;
- «дублировать» кладёт копию со сдвигом на шаг сетки, «сдвинуть
  вверх/вниз» двигает закреплённый блок по холсту (незакреплённый —
  меняет порядок, как в потоке);
- блок, родившийся рядом с закреплённым (Enter, вставка), встаёт **под
  ним** (`pin_below`), а не уезжает в колонку потока в углу холста;
- вставка из меню разбирает то, что действие реально создало
  (`settle_inserted`): таблица и код добавляют **свой** блок рядом с
  заготовкой, координаты достаются ему, а пустые служебные параграфы
  выбрасываются; каретка встаёт внутрь блока в его режиме (ячейка
  таблицы, тело кода, текст);
- фон рисует сетку выбранного вида (`--doc-grid-color`);
- **страница прокручивается и по горизонтали**: блок, ушедший за правый
  край, растягивает холст (распорка `Chrome::extent` считает габарит по
  всем закреплённым блокам), и у `Page` появляется горизонтальная полоса.
  Для этого в свободной раскладке `editor_pane` берёт `Page::both()`, а
  колонка потока внутри холста получает `Chrome::fill_width` — ширину
  видимой области (containing block) вместо бесконечной ширины Stack'а,
  иначе она ужималась бы к своим строкам и уезжала в левый край. В потоке
  остаётся `Page::vertical()`;
- поток включается вручную тем же переключателем — координаты при этом не
  стираются и вернутся при обратном включении.

Координаты живут в `Attrs` блока (`x`/`y`/`w`) — их таскают за собой
дублирование, перенос и удаление; на диск они уходят хвостовым служебным
блоком ```` ```doc-layout ```` (строка «индекс x y w»), который
`parse_document` снимает обратно. Инлайном ключи геометрии не пишутся —
у параграфа, таблицы и разделителя нет места под атрибуты.

**Геометрия блоков.** Каждый верхнеуровневый блок обёрнут `Chrome`'ом,
который публикует свой прямоугольник в `BlockRectMap` — в обоих режимах.
Реестр строк знает только про текст, поэтому раньше у таблицы, кода, медиа,
врезки и разделителя не было ни ручки ⋮⋮, ни точной цели дропа. Ручка,
hover, цель дропа и координаты при переносе считаются теперь по этой карте.

## Свойства блока

Панель «Свойства» ниже свойств страницы показывает текущий блок (каретка
либо выбор в дереве блоков) и правит его переопределения поверх темы:
цвет текста, подложка, кегль, начертание, выравнивание. Всё это —
инлайн-атрибуты блока (`{color=#e05 size=22 align=center}`), поэтому
переживает дублирование, перенос и round-trip markdown. Пустое значение
снимает атрибут — блок возвращается к теме.

У блоков без своего места под `{…}` в markdown (параграф, список, код,
таблица, разделитель) атрибуты уходят тем же хвостовым служебным блоком,
что и координаты свободной раскладки: строка `индекс {k=v …}`. Старый
позиционный формат `индекс x y w` читается по-прежнему.

Тип блока добавляет свои операции: у таблицы — добавить/удалить строку и
колонку (`DocOp::Table`), позиция берётся от каретки в ячейке.

Габариты блока видно в документе: под курсором — лёгкая заливка, у
текущего — рамка (`--doc-block-hover-color`, `--doc-block-selected-color`).
Ручка ⋮⋮ и подсветка теперь появляются по наведению, не дожидаясь клика.

## Примитивы, картинки и SVG

Правый клик в документе → «Вставка»:

- **Примитивы** — прямоугольник, овал, треугольник, ромб, линия, стрелка,
  двойная стрелка, кривая Безье и кривые со стрелками. В markdown это
  врезка со своим префиксом:
  `![[shape:rect]]{fill=#243149 stroke=#6ea8ff sw=2 radius=8 opacity=70}`.
  Неизвестный вид (`![[shape:зигзаг]]`) остаётся обычной врезкой, а не
  теряется. Тот же набор есть в `/`-меню и в «Превратить в» (смена вида
  сохраняет оформление и координаты).
- **Канбан-доска** и **диаграмма Ганта** — свои пункты меню вставки над
  «Примитивами» (и в «/»-меню): объекты проекта, см. следующий раздел.
- **Картинка… / SVG-файл… / Файл…** — диалог выбора, файл кладётся
  вложением в бандл (`asset:<sha>.<ext>`) и вставляется медиа-блоком.
  **SVG из буфера** берёт разметку из буфера обмена и делает из неё такое
  же вложение; растеризует resvg (feature `svg` у syngui).

**Геометрия.** Рамочная фигура занимает прямоугольник блока: ширина — `w`
свободной раскладки, высота — новый ключ `h` (у картинки он тоже работает).
Линейная фигура задаётся двумя концами `x1 y1 x2 y2` в координатах внутри
блока, кривая — ещё двумя направляющими `cx1 cy1 cx2 cy2` (кубическая
Безье). Рамка — bbox всех точек плюс поле 12 px под наконечники и хваталки:
кривая целиком лежит в выпуклой оболочке своих четырёх точек, поэтому такой
bbox её всегда накрывает. Пока направляющие не трогали мышью, они выводятся
из концов — плавная S-дуга по длинной оси, как провода нодового редактора. Модель держится в каноничном виде: минимум концов равен нулю, а
рамка сдвигается под них — поэтому перенос за ручку ⋮⋮ и растяжение
работают для линии так же, как для остальных блоков.

**Мышь в свободной раскладке.** Правая кромка — ширина, нижняя — высота,
правый нижний угол — то и другое сразу, кружки на концах линии — сами
концы, а у кривой добавляются две маленькие точки-направляющие на
поводках (курсоры `ColResize`/`RowResize`/`SeResize`/`Crosshair`).
Линию под наконечником стрелки укорачивает `trim_front` по её ломаной —
у кривой направление острия берётся из касательной последнего сегмента. Клик по
фигуре делает её текущим блоком: каретки внутри неё нет, поэтому у
редактора появился «выбранный объект» (`object_sel`) — от него же работают
дублирование, удаление и сдвиг из контекстного меню. У линии зона клика —
сам отрезок, а не его bbox.

**Настройка** — панель «Свойства» ▸ «Фигура»: вид, заливка, обводка,
толщина, пунктир, скругление (у прямоугольника), прозрачность; ниже —
«Размер» с точными шириной и высотой. Всё это атрибуты блока, то есть
переживает дублирование, перенос и round-trip markdown. `stroke=none`
убирает контур (у фигуры остаётся только заливка).

## Канбан-доска и диаграмма Ганта

Примитивы-объекты: блок `![[kanban:<id>]]{h=400}` / `![[gantt:<id>]]{h=340}`
над файлом `notes/objects/<id>.kanban.json` / `.gantt.json` в бандле
(`kanban/model.rs`, `gantt/model.rs`). Ручки живут в пуле
`NotesCtx.objects` (`LiveObject::{Kanban, Gantt}`), автосейв подписан на их
`revision`; удаление и дублирование страницы таскают объекты за собой
(`state::object_refs`, виды — `OBJECT_KINDS`). Вставка создаёт объект из
шаблона и врезку сразу с высотой по умолчанию по виду объекта
(`embeds::default_object_h`: доска 400, диаграмма 340); колонки доски по
умолчанию 300 px (`kanban::model::DEFAULT_COLUMN_WIDTH`).
Оформления у такого блока нет: ни рамки и шапки врезки, ни фона и полосы
`Chrome`'а, ни подсветки/рамки выбора в редакторе — доска и диаграмма
выглядят сами по себе (`build.rs` отдаёт виджет хоста как есть, если
`has_own_height`).

**Хит-тест на холсте.** Распорка `Chrome::extent` — последний, то есть
верхний ребёнок Stack'а холста, и `hit_test_path` дерева останавливался на
ней: клики не доходили ни до одного виджета внутри закреплённых блоков
(кнопки доски, поля диаграммы), а текстовые строки этого не выдавали —
их обслуживает сам редактор. Распорка теперь `passthrough_hit_test`; тест
`embed_children_receive_clicks`. Та же природа у ползунков прокрутки:
редактор на всю область забирал MouseDown раньше `Page`, и ползунок
нельзя было тянуть — `Page` и `ScrollView` теперь отвечают
`ChildHit::None` над видимым ползунком, и клик достаётся им. Зоны
растяжения у доски/диаграммы есть (нижняя и правая кромка, угол), но
полоски не рисуются — они читались как рамка вокруг блока.

**Высота.** Врезка со своей высотой — ключ `h` свободной раскладки:
редактор отдаёт его фабрике врезок в `EmbedCtx.height`, а
`EmbedFactory::has_own_height` говорит редактору, что у такого блока есть
нижняя кромка для растяжения и клик по его пустому месту делает блок
текущим (`object_sel`). В панели «Свойства» у доски и диаграммы — только
секция «Размер».

**Доска** (`kanban/view.rs`): колонки в горизонтальной прокрутке. Шапка
колонки: цветная метка (клик — следующий цвет палитры `PALETTE`),
название (TextField, пишется по Enter/уходу фокуса), счётчик,
«+ карточка»; правая кромка колонки тянет её ширину
(`drag_strip.rs` — свой элемент, отдаёт приращения по X; текущая ширина
берётся из документа, потому что доска перестраивается на каждый шаг).
Добавление и удаление колонок (карточки переезжают в соседнюю), ширины и
**внешний вид** (`KanbanStyle`: общая ширина колонок, фон колонки, фон
карточки — полупрозрачные оттенки `TINT_PRESETS`, счётчики) — в панели
«Свойства» при выбранной доске (`right_panel::kanban_props`), а не на
самой доске.

Карточка — **заголовок + markdown-содержимое + поля** с цветной полосой
своей колонки. В просмотре: бейдж приоритета и метки (сколько влезает по
ширине, остальное — «+n»; цвет метки — по её тексту, `model::tag_color`),
заголовок, первые три строки содержимого без разметки
(`model::preview_text`), в подвале — срок (`MI_TODAY` + `ДД.ММ`,
просроченный — красным) и прогресс чек-листа по `- [ ]`/`- [x]`
содержимого (`model::checklist_progress`, «2/5» + `ProgressBar`; в
файле не хранится). Поля карточки (`KanbanCard`): `priority`
(`low|medium|high|urgent`), `tags`, `due` (ISO `yyyy-mm-dd`) — пустые
не сериализуются, старые json читаются. Клик — правка на месте **одним**
`DocumentEditor`: первый блок `## …` — заголовок, ниже — содержимое
(`compose_card` / `split_card`), ручка + исходник на момент начала
правки из `KanbanHandle::card_editor` (стабильный отпечаток, иначе
каждая перестройка перепарсивала бы модель), автофокус с кареткой в
заголовке. Редактор карточки — `plain(true)` (без ручки ⋮⋮, подсветки и
рамки блока: в карточке они читались как мусор) с подсказками
`heading_placeholder` «Заголовок» и `placeholder` «Описание, чек-лист…»
в пустом заголовке/абзаце — Enter в заголовке открывает абзац описания.
Правку закрывает **потеря фокуса** (`on_focus_lost`) — клик куда угодно
ещё; для этого редактор syngui получил роль a11y `TextField`. Пустая
карточка при закрытии выбрасывается.

**Фокус страницы и врезка.** Приложение отдаёт фокус по клику самому
глубокому текстовому вводу под курсором, и редактор страницы заявлял себя
всей своей областью — вместе с доской внутри: клик по метке цвета колонки
или пустому месту доски оставлял каретку живой в заголовке над ней.
Теперь редактор над любой врезкой фокус не берёт (`Element::text_input_hit`
в syngui), приложение снимает с него фокус, а клик в пустое место
врезки-объекта лишь делает её текущим блоком для панели свойств
(`select_object(id, focus = false)`). Клик обратно в текст возвращает
каретку как обычно.

**Выбор и поля.** Клик по карточке делает её ещё и *выбранной*
(`KanbanHandle::selected`); у выбранной под текстом — поля столбиком
(`view::card_fields`: приоритет `Dropdown`, срок `DatePicker`, метки
`TextField` через запятую + «удалить»; ширина — `field_width` от ширины
колонки, в ряд они в 260 px не влезали), и те же поля дублирует панель
«Свойства» (секция «Карточка» в `right_panel::kanban_props`). `DatePicker`
и его календарь красятся глобальным правилом `DatePicker {}` в
`reset.mss` (`--cal-*`) — без него поле и панель были белыми. Падение при
наборе меток: после submit хост отдаёт полю нормализованный текст
(«,» → «, »), а каретка оставалась на старом байтовом смещении внутри
кириллической буквы — `TextField::update` теперь снимает её на границу
символа, а батчер рендера страхует срезы (`snap_boundary`). Выбор
переживает закрытие правки — иначе клик по полю (он уводит фокус из
редактора карточки и закрывает правку) перестраивал бы карточку прямо
под курсором и терял поле. Клик по пустому месту колонки снимает выбор.
Сигналы ручки: `revision` — автосейв на каждую правку, `structure_rev` —
только перестройка вида (набор в карточке стекает в документ без
пересоздания редактора).

**Перенос и цели дропа.** Карточка — `Draggable` (payload
`<доска>|<карточка>`); цели — **вся колонка**: `DropArea` каждой
карточки (верхняя половина — «перед ней», нижняя — «после»,
`DropInfo::size`) и `DropArea` тела колонки (пустое место и хвост — «в
конец»), плюс `DropArea` всей доски, который поглощает дроп мимо колонок
(шапка, зазор), чтобы он не ушёл на страницу. Раньше цели были только
сама карточка и полоска «+ Добавить карточку» внизу — дроп в пустую
колонку не срабатывал вовсе. Дерево syngui отдаёт `DragMove`/`Drop`
**самой глубокой** цели под курсором (`ElementTree::dispatch_drag_event`),
и только если она не взяла — следующей; поэтому вложенные DropArea
(карточка внутри редактора страницы, который сам цель для файлов) больше
не спорят. Место вставки (`model::DropSpot`) показывает
**плейсхолдер** — пустая карточка высотой с переносимую (`view::gap`:
свой `Reactive` на каждый зазор по сигналу `hover`, чтобы доска не
перестраивалась на каждое движение и карточка-источник жила — призрак
переноса в syngui теперь её живой снимок; высота — из
`Draggable::on_drag_start`). Своё место карточки не подсвечивается.
Перенос между досками одной страницы — `drop_card`: изъятие у источника,
вставка сюда (`Boards` — поиск доски по id из пула объектов).

**Блоки ↔ карточки.** Перенос блока за ⋮⋮ редактор объявляет ещё и
drag'ом дерева (`DocumentEditor::block_drag_type`, тип
`sinks::DRAG_TYPE_BLOCK`, payload — id блока, `DragData::without_ghost`
— блок и так виден), поэтому его принимают те же `DropArea` колонок с
тем же плейсхолдером: блок становится карточкой в месте дропа
(строка-заголовок или единственная простая строка — заголовком,
`split_block`), а хост забирает его markdown и ставит `DocOp::DeleteBlock`
(`sinks::take_page_block`, `BoardEnv::take_block`). Отпускание при drag'е
дерева приходит редактору как `DragEnd` (`ElementTree::end_drag`, MouseUp
дереву не шлётся); над доской редактор не рисует свой индикатор вставки
(`sized_embed_at`). Обратно: карточка, отпущенная на документ мимо
досок (`on_drop_data`, тип `notes-kanban-card`), становится блоками
страницы в точке дропа (`DocOp::InsertMarkdownAt`, `### заголовок` +
содержимое) и уходит с доски. Прежний реестр прямоугольников
(`RectProbe`) и `on_block_drop` больше не используются.

Хвост колонки — полоса «+» без подписи (новая карточка), в шапке — «+»
кнопкой. Headless-тесты доски (`kanban/harness_tests.rs`,
`cargo test --features testing kanban`): дроп в пустую колонку, верхняя/
нижняя половина карточки, своё место без плейсхолдера, две доски на
странице, блок страницы за ⋮⋮ → карточка.

**Диаграмма** (`gantt/`): тулбар (новая задача — сегодня плюс два дня,
масштаб −/+, «Сегодня»), слева колонка задач из обычных виджетов (метка
цвета, название, удалить), справа шкала — свой элемент на `CanvasContext`
(`chart.rs`) с теми же высотами строк. Бар таскается целиком или за края,
кружок у правого конца тянет зависимость на другой бар, клик по стрелке
выделяет её и показывает крестик удаления; Ctrl+колесо — масштаб (пишется
в документ, `zoom`), колесо/драг фона — прокрутка шкалы. Даты уходят в
документ только на MouseUp, чтобы перестройка по `revision` не рвала жест.
Цвета шкалы — из MSS `notes-gantt-chart` (`color`, `border-color`,
`accent-color`), а не константы.

## Интеллект-карта (mindmap)

Объект `![[mindmap:<id>]]{h=420}` над `notes/objects/<id>.mindmap.json`
(`mindmap/model.rs`): узлы с родителем (у корня его нет), текстом, заметкой
(markdown), ссылкой на страницу, иконкой-эмодзи, цветом, формой
(`auto|rect|rounded|pill|ellipse|text`), флагом «свёрнут» и ручным сдвигом
`dx/dy`; порядок братьев — порядок в `nodes`; кросс-ссылки `links`
(пунктирная дуга со стрелкой и подписью); раскладка `layout` (направление
`right|left|both|down|radial`, `h_gap` между уровнями, `v_gap` между
узлами, линии `bezier|straight|elbow`); стиль `style` (палитра веток,
заливка/обводка/цвет текста, кегль, начертание, скругление, отступ, цвет/
толщина/пунктир линий, фон, иконки, макс. ширина узла); положение вида
`view` (pan/zoom, пишется без перестройки). `sanitize` чинит сирот и циклы
при чтении. `from_outline`/`to_outline` — карта из markdown-структуры
(заголовок или первый абзац — корень, списки с вложенностью — узлы,
`- [x]` даёт иконку ✓) и обратно.

**Автораскладка** (`mindmap/layout.rs`, чистая функция от документа и
метрик текста): размер узла — по строкам после переноса по `max_node_w`,
поперечный габарит поддерева — сумма габаритов детей, дети стопкой по
центру родителя, следующий уровень на `h_gap` дальше; `both` делит детей
корня по чётности на две стороны, `radial` ставит первый уровень по кругу
(сектор ∝ размеру поддерева), глубже — обычные деревья по знаку угла;
`dx/dy` переносит поддерево; свёрнутый узел прячет потомков и получает
значок «+N». Результат нормализован (минимум в `PAD`), рёбра — точки
крепления по стороне роста с направляющими на середине зазора.

**Холст** (`mindmap/canvas.rs`) — собственный элемент на `DisplayList`/
`CanvasContext` внутри `PanZoomViewport` (события в мировых координатах,
размер вьюпорта — из constraints, по нему «вписать»). Текст измеряется
`TextMeasure` дерева после `mount`. Цвет ветки — свой цвет ближайшего
предка либо палитра по индексу ребёнка корня; `auto`-форма: корень —
капсула с заливкой, первый уровень — скруглённый прямоугольник, глубже —
текст на линии. Жесты: клик — выбор, двойной клик / F2 — правка на месте
(элемент управляет своими детьми, как редактор блоками: над узлом
монтируется `Positioned(TextField)` с автофокусом, submit по Enter/потере
фокуса, Esc; пустой новый узел выбрасывается), drag узла на другой —
переподвесить (сдвиг сбрасывается), в пустоту — сдвиг поддерева с
привязкой 5 px, Ctrl+клик по узлу со ссылкой — открыть страницу, правый
клик — выбор, меню открывает обёртка `ContextMenu` в `view.rs`. Клавиши
(элемент объявляет роль a11y TextField и берёт фокус по клику; после
правки просит его обратно через `take_focus_request`): Tab — дочерний,
Enter — соседний, Delete — поддерево, Space — свернуть, стрелки — по
дереву, Esc — снять выбор. Тулбар: дочерний/соседний/удалить,
направление, «вписать», «сбросить раскладку». «В список»
(`embeds::mindmap_to_list`) заменяет врезку вложенным списком на её
страницах и удаляет объект.

**Панель свойств** (`right_panel::mindmap_props`): «Узел» — текст,
заметка (`DocumentEditor::plain` через `MindmapHandle::note_editor`,
правки стекают в документ эффектом), цвет (свотчи + `ColorPicker`),
форма, иконка, ссылка на страницу, свёрнут, сброс сдвига, удалить;
«Карта» — направление, линии, отступы, палитра (пресеты `PALETTES`:
тема/радуга/пастель/моно + свои цвета), заливка/обводка/текст узлов,
кегль, начертание, скругление, отступ, цвет/толщина/пунктир линий, фон,
иконки, макс. ширина, сброс раскладки. Ручка (`mindmap/mod.rs`): `edit`
(revision + structure_rev) и `edit_data` (только revision — pan/zoom и
заметка), `add_child`/`add_sibling` открывают правку нового узла.

Вставка — категория «Объекты» ▸ «Интеллект-карта» ▸ «Пустая карта» /
«Из текущего блока» (`doc_menu::insert_mindmap_from_block`: markdown
текущего блока → `from_outline`, блок заменяется врезкой) и `/mindmap`.
Иконки `MI_SCHEMA`, `MI_SUBDIRECTORY_ARROW_RIGHT`, `MI_LINK`; MSS
`.notes-mindmap-*` (цвета холста — `color`/`border-color`/`accent-color`/
`background-color` класса `notes-mindmap-canvas`). Headless-тесты
(`mindmap/harness_tests.rs`, `cargo test --features testing mindmap`):
клик выбирает узел, Tab монтирует редактор над новым узлом и Enter пишет
текст, двойной клик открывает правку, drag на узел переподвешивает, в
пустоту — сдвигает с привязкой, Esc в пустом узле выбрасывает его.

## Календарь

Единое хранилище событий проекта `notes/calendar.json` (`calendar/model.rs`:
`CalendarStore` — именованные календари с цветом + события: дата, конечная
дата, время в минутах, «весь день», «сделано», заметка markdown, свой цвет,
повтор `daily|weekly|monthly|yearly` с `until` и маской дней недели
`only_days`, ссылка на страницу) и
виджеты `![[calendar:<id>]]{h=480}` над `notes/objects/<id>.calendar.json`
(`CalendarDoc`: вид `year|month|week|day`, якорная дата, фильтр календарей,
стиль). Якорь — состояние сессии: пишется в JSON вместе с видом, но при
загрузке объекта из бандла (`NotesCtx::object`) сбрасывается на сегодня,
иначе «День» открывал дату, на которой календарь оставили или создали в
прошлый раз. Добавил дело в недельном виджете — оно видно в месячном на другой
странице. Хранилище живёт в `NotesCtx.calendar` (`calendar_store()` —
лениво из бандла, иначе шаблон с календарём «Личное»), автосейв подписан на
его `revision` (`SaveSource::Calendar`). `occurrences(from, to, filter)`
разворачивает повторы и многодневные события в дни диапазона (`first`/
`last` у многодневных; 31-е в коротких месяцах и 29 февраля пропускаются);
`Weekdays` — маска дней недели повтора (биты пн…вс, пусто = любые дни,
все семь дней нормализуются в «пусто»): у `daily` она выбрасывает лишние
дни («каждый будний день» — одно событие вместо дюжины), у `weekly`
превращает повтор в обход по дням маски («по пн/ср/пт»), у `monthly`/
`yearly` пропускает вхождение, попавшее не на свой день. В JSON — список
ключей `["mon","tue",…]`; читается и строкой (`"weekends"`), старые файлы
без поля — «любые дни»;
`range_of` — диапазон вида (месяц — 6 недель с первого дня недели), `lanes`
— упаковка пересекающихся интервалов по дорожкам.

**Локальное время.** `agent::time::local_offset_secs` — переопределение
для тестов (`override_offset_secs`), `TZ_OFFSET_MIN`, иначе `localtime_r`
из libc; `local_now()`/`local_today_days()` — «сегодня» и линия «сейчас»
календаря, а `gantt::calendar::today_days` теперь тоже локальный (сроки
карточек).

**Виджет** (`calendar/view.rs`): тулбар — четыре вида, ‹ сегодня ›,
подпись периода, «+ событие»; тело — сетка вида; попап события в `Stack`
без клипа. Снимок для сеток (`GridData`) собирается на каждую перестройку
(`Reactive` по `structure_rev` виджета, `revision` хранилища, выбору,
тику). Сетки — собственные элементы на `DisplayList`/`CanvasContext`
(общая заготовка `ElementBase` + макрос `element_boilerplate!`), цвета —
стиль виджета поверх MSS класса `notes-calendar-grid` (`Palette`):
- `layout.rs` — раскладка строки дней без пикселей: `segments`
  (вхождения → непрерывные отрезки; многодневные первыми, затем «весь
  день», по времени, задачи досок после событий), `pack_row` (дорожки
  first-fit через колонки строки, флаги продолжения за края) и `visible`
  (при нехватке вместимости последняя дорожка колонки отдаётся под
  «ещё n», полоса режется там, где соседняя колонка её прячет);
- `paint.rs` — общая отрисовка полос: облики `Filled` (заливка, текст по
  яркости цвета — `text_on`), `Tinted` (подложка + полоска слева —
  задачи досок/Ганта) и `Plain` (точка + время приглушённо + название —
  события со временем в стиле «плашки»); `Look::of(event_style, …)`:
  плашки — заливка «весь день»/многодневным, точка остальным; полосы —
  заливка всем событиям; точки — всем `Plain`. Текст режется по ширине
  многоточием (`ellipsize` через `TextMeasure` дерева, без него — оценка
  0.56 кегля/символ) и клипом полосы — ничего не вылезает в соседнюю
  ячейку;
- `month.rs` — 6×7, номера недель по флагу, «сегодня» кружком; полосы по
  `layout`: многодневное — одна полоса через ячейки с плоским краем там,
  где продолжается за строку; не влезло — «ещё n» в последнем слоте
  ячейки (клик — список дня), наведение подсвечивает полосу. Клик по дню
  — выбор, двойной — новое событие, клик по полосе — попап правки,
  перенос — `move_event` на разницу дней от собственной даты события
  (полоса, взятая за середину, и повтор не прыгают началом в день
  броска; мутация на MouseUp), клик по маркеру слева (квадратик на
  заливке, точка в `Plain`) — «сделано», по внешней полосе — страница
  объекта;
- `year.rs` — 12 мини-месяцев (4×3 / 3×4 / 2×6 по ширине), точки событий
  по цвету, клик по дню — дневной вид, по названию — месячный;
- `timegrid.rs` — неделя/день: шапка, ряд «весь день» (те же дорожки
  `layout` через колонки, до 6, дальше «ещё n» → список дня), окно суток
  `CalendarStyle::window()` слотами `slot_min` (расширяется под события и
  задачи с часами в видимых днях — событие в 22:30 получает свой слот,
  настройка не меняется), дорожки пересечений, линия «сейчас»; текст
  полос по часам с многоточием и клипом, задачи досок подложкой с
  полоской;
  окно задаётся началом и концом (`from_min`/`to_min` в минутах, свитч
  «Полные сутки» — ровно 24 часа от начала): конец не позже начала —
  окно идёт через полночь, 06:00 → 06:00 это сутки со сдвигом, 22:00 →
  06:00 — ночная смена. Тогда колонка дня показывает и ночь следующей
  даты: сетка считает смещение от начала окна (`place`/`absolute`),
  снимок берёт лишний день данных, перенос за полночь двигает дату
  события, а полные сутки и ночное окно не расширяются под события.
  Задачи и события без времени остаются в ряду «весь день» по своей
  календарной дате;
  двойной клик по слоту — новое событие в нём, drag тела — перенос со
  снапом к слоту (в неделе — и по дням; событие сдвигается на разницу от
  своей даты), drag нижней кромки — длительность.
- `popup.rs` — черновик в `CalendarHandle::draft`; поля правят сигнал без
  перестройки (иначе поле теряло бы каретку): название, даты
  (`DatePicker`), «весь день», время (`TimePicker`), календарь, цвет,
  повтор + «до», семь чипов дней недели у повторяющегося события
  (`Reactive` над своими сигналами `repeat_sig`/`days_sig`: попап не
  перестраивается на правку черновика, а все дни включены = «любой день»),
  заметка (`DocumentEditor::plain`); «Сохранить» —
  `add_event`/`update_event`, «Сделано», «Удалить». Там же `day_popup` —
  список дня по «ещё n» (`CalendarHandle::open_day`, сигналы
  `day_popup_open/day/anchor`): маркер цвета, время или «весь день»,
  название; клик по событию — попап правки, по задаче — её страница, «+»
  — новое событие на этот день; длиннее 10 строк — прокрутка. Открытие
  любого попапа закрывает другой.

**Слой сроков и задач** — `embeds::calendar_env`: `external(from, to)`
обходит все страницы проекта и собирает сроки карточек досок (цвет
колонки) и отрезки задач Ганта; объект, встроенный на нескольких
страницах, учитывается один раз (иначе каждая врезка дублировала его
карточки в календаре); включается флагами стиля
`show_kanban_due`/`show_gantt` (по умолчанию выключены), read-only, клик
открывает страницу объекта.

**Панель свойств** (`right_panel::calendar_props`): «Событие» (название,
дата, сделано, календарь, цвет, «Изменить» — попап, удалить), «Вид» (вид,
якорь, чипы календарей — пустой фильтр = все, первый день недели, номера
недель, часы, слот, компактно, слои досок/Ганта), «Стиль» (пресеты
`theme|light|contrast|pastel` — `CalendarStyle::apply_preset`, чипы/точки/
полосы, кегль, цвета «сегодня»/шапки/ячеек/сетки/выходных/текста — свотчи +
`ColorPicker`), «Календари» (имя, цвет, удалить — последний не удаляется,
события переезжают; добавить).

Headless-тесты календаря — `calendar/harness_tests.rs`.

Вставка — «Объекты» ▸ «Календарь» ▸ год / месяц / неделя / день
(`doc_menu::insert_calendar`, `NotesCtx::create_calendar(view)`) и
`/calendar-month` и т. п. Иконки `MI_DATE_RANGE`, `MI_CALENDAR_MONTH`,
`MI_CALENDAR_VIEW_WEEK`, `MI_CALENDAR_VIEW_DAY`, `MI_CHECK_BOX*`; MSS
`.notes-calendar-*`. Дублирование страницы клонирует только объект-вид
(события общие), удаление виджета события не трогает.

## График (chart)

Объект `![[chart:<id>]]{h=320}` над `notes/objects/<id>.chart.json`
(`chart/model.rs`) — **отдельный блок страницы**, как доска или карта.
Рисуют его виджеты библиотеки графиков syngui
(`syngui::widgets::charts`), свои элементы синтоса тут не нужны:
`chart/view.rs` собирает из документа `LineChart`, `BarChart`, `PieChart`,
`RadarChart` или `GaugeChart`.

**Документ** один на все пять видов: `kind`, заголовок `title` (рисует сам
виджет), подписи `categories`, цвета подписей `colors` (используются
круговой), ряды `series` (`id`, имя, цвет, `data: Vec<f64>`) и `options` —
общая копилка настроек: легенда (`top|bottom|left|right|none`), подсказки,
анимация, сетка и заголовки осей с границами `y_min`/`y_max`, сглаживание/
точки/заливка (линии), стопка/горизонталь/подписи значений/скругление
(столбцы), кольцо/подписи долей/проценты (круговая), круглая сетка/уровни/
потолок (радар), границы/стрелка/деления/подписи/единица/цветные зоны
(шкала). Поля, которых вид не понимает, просто не читаются — **смена вида
ничего не теряет**: вернув вид назад, пользователь получает свой график.
`sanitize` держит подписи и ряды одной длины (по максимуму: молча резать
числа нельзя), у круговой и шкалы оставляет один ряд, а у шкалы — одно
число.

Подписи у линий — не отдельный тип оси, а `AxisConfig::format`: значения
ложатся на X = 0…n−1, форматтер отдаёт подпись для целых делений (делений
не больше 12, шаг оси «красивый», так что на длинном ряде подписи идут
через одну). У радара потолок осей общий (разные максимумы у соседних
лучей делают фигуру нечитаемой): `radar_max` либо `max × 1.15`.

**Размер** — из врезки: MSS-класс `.notes-chart` задаёт `width/height:
100%`, иначе виджет берёт встроенные умолчания библиотеки (600×400 у
линий, 300×300 у круговой) и висит куском в углу блока. Цвета осей,
подписей и заголовка графики выводят из `color`, поэтому одной строки
`color: var(--text)` хватает на всю тему; радару нужен ещё явный
`background-color` — его умолчание белое.

**Правится график только в панели свойств** (`right_panel::chart_props`) и
инструментом агента: на самой картинке нет ни тулбара, ни рамки — блок
целиком отдан графику. Панель: вид (иконки-переключатель), заголовок;
«Данные» — у шкалы значение с границами, единицей и цветными зонами, у
круговой список долей (подпись, число, цвет, удаление), у остальных поле
подписей через запятую и на каждый ряд имя, значения через запятую и цвет;
«Оформление» — общие настройки и то, что понимает текущий вид. Разделитель
списка значений выбирается по строке: есть «;» — режем по нему (тогда
«2,5» остаётся одним числом), иначе по запятой, а без неё — по пробелам.

Вставка — категория «Объекты» ▸ «График» ▸ вид (линии, столбцы, круговая,
радар, шкала) или «Из таблицы» (`doc_menu::insert_chart_from_table`:
текущий блок-таблица → `ChartDoc::from_table`, шапка даёт ряды, первая
колонка — подписи), и `/`-меню (`chart-line`, `chart-bar`, `chart-pie`,
`chart-radar`, `chart-gauge`, `chart-table`). Иконки `MI_SHOW_CHART`,
`MI_BAR_CHART`, `MI_PIE_CHART`, `MI_HUB` (радар), `MI_SPEED` (шкала).

**Правка в syngui** (`charts/line_chart/element.rs`,
`bar_chart/element.rs`): клик мимо легенды, точки и зума график больше не
поглощает (`EventResult::Ignored`). Пока он возвращал `Handled`, клик по
врезке не доходил до редактора — блок не выбирался, и панель свойств
графика было не открыть. У круговой и радара так было изначально.

Headless-тесты (`chart/harness_tests.rs`, `cargo test --features testing
chart::harness_tests`): график занимает блок целиком (ширина 800 > своего
умолчания), смена вида меняет виджет и не теряет данные, клик по графику
выбирает блок врезки, все пять видов монтируются.

## Редактор (syngui, feature `document-editor`)

«Пассивные строки»: блоки — дочерние элементы, весь ввод — у контейнера
(каретка/выделение/IME/undo/выделение блоков). Хост общается через
`DocumentEditorHandle`:

- `serialize()`, `revision()` — автосейв; `append_markdown()`,
  `patch_media()`;
- **`layout(DocLayout)`** — поток либо свободная раскладка (сетка,
  привязка, ширина нового блока); `fill_height(bool)` — держать высоту
  не меньше видимой области; `plain(bool)` — без обвязки блоков (ручка
  ⋮⋮, подсветка/рамка, зоны растяжения) для встроенных редакторов;
  `placeholder` / `heading_placeholder` — подсказки в пустом абзаце и
  заголовке; `block_drag_type` — перенос блока за ⋮⋮ как drag дерева. Курсор над ручкой ⋮⋮ — «рука» (`Grab`), над
  правой кромкой — `ColResize`, во время переноса — `Grabbing`;
- **`queue_op(DocOp)`** — операции «у текущего блока» (каретка либо
  выбранный объект; в свободной раскладке вставка идёт в точку последнего
  правого клика): `InsertMarkdown`, `InsertBlock(SlashAction)`,
  `TurnInto(SlashAction)`, `Duplicate`, `Delete`, `Move{down}`,
  `Undo`/`Redo`, `Copy`/`Cut`/`Paste`, `SelectBlocks`. Применяются самим
  элементом на ближайшем `update` (хост бампает `.model_epoch(..)` —
  `NotesCtx.doc_epoch`), так что правка проходит через undo и ставит
  каретку в новый блок;
- **`history_state()`** — сигнал `(можно отменить, можно повторить)` для
  кнопок ↶ ↷ в шапке центра (`mod.rs::history_buttons`); **история
  undo/redo живёт в ручке**, как и модель: иначе смена плитки или страницы
  теряла бы её. Кнопка уводит фокус приложения с редактора — операция
  `Undo`/`Redo` просит его обратно (`focus_request_pending`);
- **`block_selection()`** — сигнал выделенных блоков верхнего уровня;
  панель «Блоки» подсвечивает их строки.
- `on_context_menu(Point)` — правый клик: редактор ставит каретку в точку
  клика (непустое выделение сохраняется, если клик внутри него) и отдаёт
  позицию; без колбэка правый клик не перехватывается.

**«Ctrl+Z не работает».** Корень был не в истории: приложение слало
`CharInput` и при зажатом Ctrl, а в русской раскладке xkb на Ctrl+Z отдаёт
текст «я» (control-преобразование только для ASCII) — буква вставлялась,
а следом `KeyDown(Z)` откатывал ровно эту вставку. Теперь `AppHandler` не
шлёт текст при Ctrl (кроме AltGr = Ctrl+Alt в Windows) и Cmd, а редактор
дублирует фильтр у себя (как `TextField`).

**Выделение блоков и буфер обмена.** Отдельный режим редактора
(`block_sel`): Ctrl+клик переключает блок, Shift+клик тянет диапазон от
якоря, клик по ручке ⋮⋮ без переноса выделяет блок, нажатие в пустом
месте (поля, холст, ниже текста) с протяжкой — рамка по всем блокам,
которых она касается (без протяжки на отпускании ставится обычная каретка,
как раньше); повторный Ctrl+A (весь текст уже выделен) выделяет все блоки,
Esc снимает, ↑/↓ шагают по блокам (с Shift — растят диапазон). Над
выделением: Delete/Backspace удаляет одним шагом истории, Ctrl+C/X кладут
блоки в буфер как markdown (блоки через пустую строку), Ctrl+V ставит
блоки из буфера после последнего выделенного. Ctrl+V без выделения:
однострочный текст — в строку, многострочный — блоками markdown
(структура из другого редактора и наши копии блоков сохраняются). Те же
действия — в контекстном меню документа и строки панели «Блоки»
(`doc_menu::block_action_items`: копировать/вырезать/вставить); правый
клик по выделенному блоку выделение сохраняет. В `plain`-редакторе
(карточка доски) режима нет.

**Модель живёт в ручке.** `create_element` больше не перепарсивает
`markdown(..)` поверх модели, уже загруженной из того же исходника
(отпечаток хранится в `DocumentEditorHandle`): иначе размонтирование
поддерева — переключение плитки рейла или страницы — теряло все правки,
сделанные после открытия. Смена самого исходника модель по-прежнему
заменяет (перезагрузка страницы).

Редактирование блоков без текстовых строк: у таблицы своя каретка
(`table_caret`), у кода — своя (`code_caret` + `CodeGeomMap`, который
публикует `CodeBlockElement`): клик ставит каретку внутрь кода, Enter даёт
перевод строки, Tab — четыре пробела, стрелки вверх/вниз за границей блока
выходят в документ, Escape выходит сразу. Строка заголовка выноски строится
всегда, даже пустая — без неё у блока не было геометрии и он не
редактировался.

Остальное без изменений: slash-меню «/», markdown-шорткаты, инлайн-тулбар,
автокомплит `[[`, ручка ⋮⋮, инъекции `DocLinkProvider` / `DocMediaResolver`
/ `EmbedFactory`, MSS `document-editor` + `--doc-*`.

## Расширенный markdown

`[[Название]]` — wiki-ссылка на страницу (резолв по названию без регистра,
`index.rs`); `![[Название]]` — врезка страницы read-only (глубина ≤ 2,
циклы отсекаются по цепочке id); `![[kanban:<id>]]` / `![[gantt:<id>]]` —
живые редактируемые объекты (`embeds.rs`, ручки из пула
`NotesCtx.objects`). Callout `> [!kind]{color=#…}`, toggle `[!toggle]`,
инлайн-атрибуты `{k=v}`, медиа-блоки — как в первой волне.

**Что toggle сворачивает.** Содержимое сворачиваемого блока (и выноски, и
цитаты) — это его дети, а в markdown — строки цитаты: `> [!toggle]
Заголовок` и дальше **каждая** строка с `> `, строки таблицы в том числе.
Написанные подряд toggle и таблица без префикса — два соседних блока, и
шеврон сворачивает пустоту. Вложить уже написанное можно, не трогая текст:
Tab / Shift+Tab либо пункты меню блока «Вложить в блок выше» / «Вынуть из
блока» (`DocOp::Indent` → `edit::indent_block`). Целевой блок берётся как у
остальных операций хоста (`target_block`), так что вкладываются и блоки без
каретки — таблица, картинка, врезка; координаты холста при вложении
снимаются (геометрия живёт только у верхнего уровня), а свёрнутый toggle
раскрывается, иначе блок выглядит пропавшим. Агент делает то же самое через
`blocks op=nest` / `op=unnest` (см. `notes_agent_tool_2026.md`).

## Ведение жизни: штампы, повторы, архив, журнал, напоминания (08.09.2026)

Запрос: «использую заметки в связке с ИИ для ведения своей жизни» — не
хватало истории изменений, сроков в календаре, правил вроде «сделано →
дата», ссылок-дат. Решения:

- **Колонка «готово»** — флаг `KanbanColumn.done` (панель свойств: галочка у
  колонки; третья колонка шаблона — «готово»; у старых досок и досок с
  колонками от агента флаг узнаётся по названию — `DONE_COLUMN_NAMES`,
  при разборе файла `KanbanDoc::parse` → `detect_done_column`).
- **Штампы карточки** — `created` (день появления) и `done` (день
  переезда в колонку «готово», снимается при возврате). Ставятся не в
  местах вызова, а одной доводкой после любой правки —
  `KanbanDoc::reconcile(before, today)` внутри `KanbanHandle::edit`:
  снимок до/после, поэтому мышиный перенос и вызов агента ведут себя
  одинаково. В карточке — «✓ ДД.ММ» вместо срока у закрытой, строка
  «Создана · Сделана» под полями и в панели свойств.
- **Повтор** (`KanbanCard.repeat`, тот же `Repeat`, что у событий):
  закрытие рождает следующую карточку в первой открытой колонке — тот же
  текст с неотмеченным чек-листом (`uncheck`), срок сдвинут на период от
  большего из срока и сегодня (`next_period`; просроченная привычка не
  тянет хвост пропусков). Выпадающий список «Повтор» у карточки и в панели.
- **Архив** — `KanbanDoc.archive` (карточки вне доски, файл тот же) и
  `archive_after` (дней после закрытия; спинбокс в секции стиля, 0 —
  выключено): автоархив — часть той же доводки и `sweep` при загрузке.
  Кнопки «В архив» у карточки; в панели — «В архиве: N · Вернуть»
  (возврат — в колонку «готово» со свежим штампом, иначе автоархив унёс бы
  обратно; прежняя дата остаётся в журнале).
- **Журнал проекта** (`activity.rs`) — записи `{ts, actor, kind, action,
  object, item, title, from, to}` в помесячных файлах
  `notes/log/<yyyy-mm>.jsonl` (автосейв переписывает только грязный
  месяц — `ActivityLogHandle::take_dirty`). Источники: доводка доски
  (`CardChange` → add/delete/move/done/reopen/due/priority/archive/
  restore/repeat; переезд в «готово» — одна запись `done` с исходной
  колонкой), сверка событий в `CalendarStoreHandle::edit` (add/delete/
  done/reopen/move), операции дерева страниц (create/rename/delete).
  Актор — thread-local `activity::actor()`: инструмент агента ставит
  `Agent` на время `dispatch` (`agent_scope`), всё остальное — `user`.
  Ручка `KanbanHandle::with_log(id, log)` / `CalendarStoreHandle::with_log`
  подключается в `NotesCtx::object`/`create_object`/`calendar_store`;
  доска без журнала (тесты) просто молчит. Изъятие карточки при переносе
  между досками (`take_card`) идёт тихой правкой — запись делает
  принимающая доска.
- **Вложения карточки** — `KanbanCard.files: Vec<CardFile {url, name}>`
  над теми же File-чанками `notes/assets/<sha>.<ext>`, что и медиа страниц
  (`media::ingest_bytes`). Картинки (`CardFile::is_image` по расширению)
  — миниатюрами 64 px в карточке (`view::files_row`/`thumb`, файл из кэша
  `media::asset_file`), клик — модальное окно просмотра
  (`media::image_viewer`, `FloatingWindow` по центру, `NotesCtx.viewer_*`);
  остальные — чипы со скрепкой, клик — `xdg-open` (`media::open_external`).
  Скрепка у выбранной карточки (`view::attach_button` → `rfd` →
  `media::ingest_card_file`) и в панели свойств, список вложений с «×».
  Окружение доски `BoardEnv` получило `asset_path`/`ingest_file`/
  `open_file`/`pick_file` (`BoardEnv::detached` — для тестов без проекта).
  Агент: `kanban op=attach card path|attachment [name]` / `op=detach card
  file` — модель не передаёт байты, только путь на диске или вложение чата.
- **Копирование карточки (11.09.2026)** — `kanban/clip.rs`. Правый клик по
  карточке открывает её `ContextMenu` (раньше он доставался меню страницы,
  и «Копировать» уносил в буфер блок `![[kanban:…]]` целиком): «Копировать
  ▸» — `CopyKind::{Full, TitleBody, TitleBodyPaths, TitlePaths, Body,
  Paths, Files}` (виды с путями и файлами выключены без вложений;
  «заголовок + пути» перечисляет и картинки из текста — самого текста в
  копии нет) и «Вставить карточку» — после неё; правый клик
  по пустому месту колонки — вставка в конец. Ctrl+C — карточка целиком:
  в редакторе карточки без выделенного текста и на странице, когда
  выделен блок доски с выбранной карточкой (Ctrl+V там же вставляет после
  выбранной) — хук syngui `DocumentEditor::on_clipboard_key`.
  «Что копировать» выбирается при копировании, «в каком виде» — местом
  вставки: `syngui::clipboard::copy_rich` кладёт на Wayland несколько MIME
  одной копией (`wl-clipboard-rs`; arboard умеет один формат за раз).
  Терминал берёт `text/plain`, файловый менеджер и мессенджер —
  `text/uri-list` + `x-special/gnome-copied-files`, но только у «Вложения
  как файлы»: у остальных видов Telegram вставил бы файлы вместо текста.
  Под X11 и без data-control — только текст.
  Вложения в тексте — абсолютные пути выгрузки `media::export_card_files`:
  `~/.cache/synthos/notes-export/<проект>/<карточка>/<исходное имя>` —
  жёсткая ссылка на распакованный кэш (копия, если ссылка не вышла),
  только для чтения: агент, правящий файл «на месте», иначе испортил бы
  кэш. Лишние файлы убираются, папки без копирования дольше недели
  удаляются по метке `.copied`; ссылки `asset:…` в содержимом тоже
  становятся путями. Вставка внутри «Заметок»: последняя скопированная
  карточка запоминается в процессе вместе со своим текстом
  (`clip::remember`/`recall`), и при совпадении текста буфера вставляется
  её копия со всеми полями и вложениями (`fresh_copy`: новый id, без
  штампов; из другого проекта вложения переезжают — `carry_assets`), а
  чужой текст становится новой карточкой (`split_block`, как блок
  страницы). Тесты: `cargo test --lib kanban::clip`, харнесс —
  `cargo test --features testing kanban::harness_tests` (меню карточки и
  колонки, Ctrl+C в редакторе карточки).
- **Сроки в календаре** — слой сроков карточек и задач Ганта существовал и
  раньше, но был выключен по умолчанию, и модель «переносила руками»:
  теперь `show_kanban_due`/`show_gantt` у новых виджетов включены
  (`default_true_style`), `calendar read/list_events` агента отдаёт их по
  умолчанию с пометкой «не событие».
- **Страница дня** — `NotesCtx::journal_page(day)`: `Журнал / yyyy-mm /
  yyyy-mm-dd` (корень ищется по названию на любом языке — `JOURNAL_ROOT_NAMES`
  или `tr!("notes.journal.root")`, иначе создаётся с иконкой `MI_TODAY`);
  ссылка `[[yyyy-mm-dd]]` (`state::date_title`) в `links.rs` открывает или
  создаёт её; кнопка «Страница дня» в шапке «Содержимого» и в попапе
  напоминаний; агент — `journal {date, content, mode}`.
- **Напоминания** (`reminders.rs`) — из данных, без скриптов: карточка с
  `due` (не закрытая) напоминает в день срока, за день до него и, пока
  просрочена, каждый день; событие — за N минут до начала (весь день — во
  «время сроков»). Настройки и «что уже показано» — `notes/reminders.json`
  (`ReminderState`; ключи `card:<id>:<вид>:<день>` / `event:<id>:<день>`,
  обрезка старше месяца). `install_reminders` (lib.rs, после автосейва
  заметок): первая проверка через 6 с после запуска, дальше раз в минуту
  (`tokio::sleep` → `run_on_main_thread(check_now)`); `check` собирает
  список (`collect`: доски + `occurrences` календаря на сегодня/завтра),
  кладёт его в `NotesCtx.reminders` и показывает тосты приложения
  (`AppCtx.notifications`, 30 с; больше четырёх — три плюс «и ещё N») тем,
  чьё время сегодня уже пришло и кто не показан. Колокольчик в шапке центра
  (`reminders::bell`, бейдж = просрочено + сегодня + события сегодня) →
  попап (`PopupPanel`): секции Просрочено / Сегодня / События / Завтра,
  клик по строке открывает страницу, внизу настройки (включено, время,
  «за день до», минуты до события) и «Страница дня».

Почему не Lua/скрипты в бандле: напоминания и правила «сделано → дата»
выводятся из данных, а исполняемый код в проекте — это отдельная поверхность
атаки и отладки для локальной модели; если понадобятся произвольные правила,
они лягут декларативным JSON поверх этих же доводок.

## Порядок страниц в дереве «Содержимое» (08.09.2026)

Жалоба: «DnD только вкладывает страницы друг в друга, порядок не
меняется». Логика «перед/после» в обработчике была, но кромки по 7px из 28,
без индикации, а между строками стоял зазор в 1px, в который дроп проваливался.

Теперь (`contents.rs`): зоны считаются от высоты цели (`zone_at`: верхние и
нижние 30% — «перед»/«после», середина — «внутрь»); над каждой строкой и
под последней — линия вставки 2px (`drop_line`, `.notes-tree-drop-line`),
которая красится, пока подсказка `NotesCtx::tree_drop` (`TreeDropHint::
Line | Tail | Into`) указывает на неё; «внутрь» — рамка на строке
(`.notes-tree-row.drop-into`). Сам перенос считает `drop_plan(tree,
expanded, src, target, zone)` → `(родитель, индекс)` для
`NotesCtx::move_page`: индекс после изъятия источника, то же место — не
перенос, в собственное поддерево — нельзя, нижняя кромка раскрытой страницы
с детьми — первым ребёнком (линия там рисуется над первым ребёнком).
Подсказка гаснет при уходе курсора с дерева (внешняя `DropArea`) и на
дропе. Реактивен только бокс строки — `Draggable`/`DropArea` живут, перенос
не рвётся. Порядок хранится порядком `children` в `tree.json` — ничего
нового не пишется. Тесты — `contents::tests`.
