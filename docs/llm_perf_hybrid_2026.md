# Перф гибридных LLM (Qwen3.6/3.8-27B) — раунд 2026-08-15

Железо: RTX 5090 Laptop 24 ГБ, NVFP4 (attn+mlp+lm_head), compute F16.
Замеры: `synaptix run … --quant nvfp4 --temperature 0 --warmup`, 128 токенов.

| Метрика | До | После |
|---|---|---|
| Prefill длинного промпта | **OOM при ≥512 ток** (single-shot) | 3348 ток за 2,3 с (**1452 ток/с**), пик VRAM 22,0 ГБ |

## Что сделано (synaptix)

1. **Дисковый кэш NVRTC** (`kernels/compile.rs`): source→PTX кэшируется в
   `~/.cache/synaptix/nvrtc` (ключ: исходник+опции+arch+версия NVRTC, сверка
   побайтовая; `SYN_NVRTC_CACHE=0` выключает, `SYN_NVRTC_CACHE_DIR` переносит).
   PTX→SASS и так кэшируется драйвером; вместе — холодный старт без
   секундных пауз на каждой новой M-форме GEMM.

2. **Чанкованный префилл по умолчанию** (`pipeline.rs::prepare_cfg`):
   `prefill_batch=0 → 256`, любое значение округляется к кратному 64.
   Кратность обязательна: границы чанков на некратных CS=64 позициях ломают
   состояние GDN-скана (`prefill_chunk_divergence`: 64/128/256 — bit-exact к
   single-shot, 47/73/100 — расходятся). Проверено на T=1500: chunk 256 vs 128
   — побайтово идентичны. Это снимает главный лимит: single-shot M≥512 не
   влезал в 24 ГБ поверх ~18 ГБ весов.

3. **Батч-проекции в small-s пути linear-attn**
   (`model.rs::forward_small_batch_dev`): для s≤8 (MTP verify s=2) in_proj и
   out_proj читают веса один раз (M=s GEMM) вместо s раз; рекуррентное ядро —
   по токенам (state-зависимо, весов не читает). Verify 35,2→33,3 мс/шаг.
   `SYN_LA_SMALLBATCH=0` — старый цикл.

4. **Пофазный профиль MTP-цикла** (`SYN_MTP_PROF=1`): draft / snapshot /
   verify / sample / advance / restore с sync-границами. Текущий расклад:
   verify 92,5%, draft 3,4%, остальное <2% — узкое место известно.

## Почему decode ~47 ток/с — это потолок текущей схемы

Один verify-проход (s=2) читает все ~14,6 ГБ NVFP4-весов ≈ 26-28 мс — чистая
полоса памяти. MTP даёт 1+p токена за проход (p≈0,8 → 1,78 факт). Дальше
только цепочка драфтов глубины 2 (verify s=3), но на гибриде с linear-state
частичный реджект требует повторного verify-прохода (state не отматывается
частично), что по матожиданию съедает почти весь выигрыш при p≈0,8 —
отложено. Alternативы: спекуляция без отката (tree-verify с несколькими
снапшотами state) или FP4-KV.

## synthos

Дефолт `qwen36_prefill_chunk` 1024→256 (единственный безопасный размер на
24 ГБ; движок всё равно округлит к 64). Ничего больше менять не нужно — фасад
и Syn-чат получают всё автоматически.

## Регрессии/инструменты

- `prefill_chunk_divergence MODEL.syn T chunk [ref_chunk]` — ref_chunk для
  чанк-vs-чанк сравнения на T, где single-shot не влезает в VRAM.
- Гейтед e2e: `SYN_QWEN38_BUNDLE=… cargo test -p synaptix --release --test
  qwen38_facade_smoke`.
- Известный вопрос ядру (унаследован): состояние GDN после частичного
  ВНУТРЕННЕГО чанка (s%64≠0 mid-stream) неточное; на выровненных границах не
  проявляется, single-shot затрагивает только хвост (эталон тот же).
